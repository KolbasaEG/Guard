# Структура компонентов Guard

Приложение использует один основной `Layout/MainLayout`: шапка, левое меню
и содержимое страницы. `AccountLayout` сохраняет отдельное оформление входа;
`Account/Shared/ManageLayout` — внутреннюю структуру управления аккаунтом.

`App.razor` использует версионированный `blazor.web.js` для модели Blazor Web App.
`MapStaticAssets().ShortCircuit()` раздаёт скомпилированные публичные ресурсы,
включая изолированные стили и загрузчик. Проверки страниц и подключений `_blazor`
остаются в middleware; short circuit относится только к ресурсам манифеста.

## Оболочка и навигация

- `Layout/AppHeader` — подразделение, заголовок раздела, переключатель меню и тема.
- `Layout/AppSidebar` — логотип, имя пользователя, учётная запись, подразделение, навигация и версия.
- `Layout/UserMenu` — отдельные кнопки профиля, смены пароля и выхода рядом с темой.
  Выход выполняется POST-формой с antiforgery; на статических страницах Identity
  смена пароля доступна обычной ссылкой, в интерактивном режиме — диалогом.
- `Layout/Navigation/NavigationCatalog` — группы, URL и условия видимости пунктов.
- `Layout/Navigation/AppNavigation` — поиск, избранное и сворачиваемые группы RadzenAccordion.
- `Layout/Navigation/NavigationEntry` — ссылка и кнопка добавления/удаления из избранного.

Одновременно раскрывается одна группа. При прямом переходе автоматически
раскрывается группа текущей страницы. Поиск работает по названиям разделов
и групп, независимо от раскрытия; очистка возвращает обычное меню.
Пустые группы, недоступные результаты и недоступные избранные ссылки скрываются.
На статических страницах Identity группы отображаются через нативные `details`,
чтобы ссылки оставались доступны без интерактивного Blazor; поиск и изменение
избранного включаются в интерактивном режиме.

Избранное сохраняется через `wwwroot/js/navigation-preferences.js` в localStorage
отдельно для каждой учётной записи и браузера. Оно не синхронизируется между
устройствами. При запрете хранилища изменения остаются в памяти до закрытия страницы.
После отзыва permissions запись может оставаться в настройках, но не отображается;
при восстановлении permissions снова становится доступной. Неизвестные URL из
хранилища отбрасываются. Смена аккаунта очищает состояние перед загрузкой его настроек.

Логотип, поиск и данные пользователя закреплены; прокручивается список разделов.
На невысоких экранах блок пользователя становится компактнее. Меню автоматически
сворачивается на узком экране и открывается кнопкой в шапке.
При ширине до 768 px панель открывается слева поверх рабочей области и не занимает
колонку сетки. Селекторы `MainLayout` намеренно специфичнее правил Radzen: CSS темы
подключается после изолированных стилей и иначе возвращает панели `position: static`.
Главная страница остаётся пустой и показывает фоновое изображение.
`Home` отслеживает `ThemeService.ThemeChanged`: для светлой темы отображается
`wwwroot/images/home-light.png`, для тёмной — `home-dark.png`. Исходный `backg.jpg`
сохранён. При смене темы фон обновляется без перезагрузки страницы.
`MainLayout` создаёт зарегистрированный `CookieThemeService`, чтобы изменения
сохранялись в `ApplicationTheme`. `App` читает cookie при первом HTTP-запросе
и передаёт восстановленную тему в `RadzenTheme`; без cookie используется `software`.

Видимость меню не заменяет авторизацию страницы и серверные проверки.
`Layout/Components/AccessStateProvider` остаётся над Router и обновляет permissions
без пересоздания маршрута. Каскадный `CurrentUserDisplayDto` передаёт основной Layout. Это снимок отображения; серверный доступ определяется независимо от него.

## Функциональные разделы

`Pages` группируется по функции, а не по роли пользователя:
`Personals`, `Subdivisions`, `Users`, `Roles`, `IpAddresses`, `Classifiers`,
`Synchronization`, `AccountPolicy`, `Logs`, `ExportArchive`.

Внутри раздела:

- `Page.razor` — маршрут, policy и композиция страницы, когда нужна отдельная точка входа;
- `Index.razor` — список и его взаимодействия;
- `Add`, `Edit`, `Details` и другие компоненты — формы и диалоги;
- `Components` — внутренние переиспользуемые части конкретного раздела.

Сложная страница синхронизации хранит композицию и код в `Synchronization/Page`.
Для политики аккаунтов используется `AccountPolicy/AccountPolicySettings`.
Файлы `.razor`, `.razor.cs` и `.razor.css` находятся рядом.

Все прежние рабочие URL сохранены. `/` и `/AdminPannel` ведут на одну главную
пустую страницу с фоновым изображением. Ссылки на участки не включены в меню:
соответствующие маршрутизируемые компоненты в проекте отсутствуют.

`Library` содержит общие оболочки и компоненты; правила их использования описаны
в `Library/README.md`. `Account` содержит Identity UI, `Exports` — общие элементы
выгрузок. Демонстрационные `Counter`, `Weather`, `Auth` сохранены с прежними URL,
но в рабочую навигацию не включены.
