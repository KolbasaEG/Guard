# Проверка доступа Guard

Прочитай применимые AGENTS.md/AGENTS.override.md и зафиксируй проверяемый diff или операцию. По умолчанию только анализ стабильного кода. Исследуй связанный путь Web → Application → Infrastructure и отрицательные тесты; не сканируй весь проект.

Проверь доступ к операции и конкретной записи на сервере. Недоверенные ID, Path, фильтры и флаги UI не могут расширять область. `[Authorize]`, имя роли «Администратор» и скрытая кнопка не доказывают разрешение операции.

Полномочия задаются permissions назначенных ролей через IPermissionService и IDataAccessScopeService; индивидуальные permission claims не учитываются. Root определяется явно, только он управляет ролями. Для обычного пользователя область — его подразделение и потомки; отсутствующий/некорректный путь означает пустую область. Проверь детали, поиск, экспорт и архив отдельно, включая подмену идентификатора и конкурентное изменение прав/дерева.

Изменение ролей/permissions проходит через IRoleAccessService с версией и транзакцией. Проверяй все IdentityResult и отсутствие ложного успеха после частичной записи. Не меняй числовые значения Status и не разрешай произвольные переходы заблокированных/архивных/удалённых записей.

IP-допуск действует до выдачи cookie и при новом HTTP/Blazor-подключении: активные IP сотрудника, пустой список запрещает доступ, Root освобождён. Периодического отзыва уже открытого соединения сейчас нет — отделяй известное ограничение от регрессии. Для HTTP установи способ аутентификации и тип endpoint, затем выбери применимые проверки CSRF/cookie. Учитывай длительный circuit InteractiveServer и актуальность пользователя.

Проверь аудит безопасности и отсутствие секретов/избыточных персональных данных в логах. Не выполняй опасные запросы на рабочей БД. Отрицательные тесты запускаются только в предназначенной среде; собственные Check-runner Guard не заменяются внешним framework.

Для каждой существенной находки верни файл/строку, условия, влияние, доказательство или воспроизведение, рекомендацию и отрицательный тест. Гипотезы пометь отдельно. При неизвестном правиле полномочий запроси решение координатора, не придумывай политику. Отсутствие находок не является гарантией безопасности. Делегирование security-агенту выполняет только координатор по правилам команды, сам Skill не запускает дополнительных агентов автоматически.
