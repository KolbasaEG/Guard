# Текущий сеанс и автор аудита

Дата: 16 октября 2026 года. Ветка: `codex/architecture-ip-search`.

## Результат

`ICurrentSession` и неизменяемый `CurrentSession(UserId, SecurityStamp)` не зависят от ClaimsPrincipal, HTTP, Blazor, Identity или EF. Это идентичность серверного сеанса, а не разрешение на операцию. DTO отображения не принимается этим контрактом.

Web-адаптер `Components/Account/CurrentSessionAdapter` сначала читает AuthenticationStateProvider. Только отсутствие активного circuit (InvalidOperationException) разрешает fallback к HttpContext. Анонимный circuit имеет приоритет над старым HTTP principal. Прочие ошибки не превращаются в успешное получение HTTP-сеанса. Снимок заново читается при каждом обращении; ожидание поддерживает CancellationToken.

`PermissionService.GetCurrentAsync` принимает этот контракт и сохраняет проверку security stamp в БД, политики аккаунта, блокировки, назначенных ролей и permissions ролей. Claims cookie не предоставляют Root или permissions. `GetForUserAsync` для фоновых задач по-прежнему работает с сохранённым автором независимо от текущего сеанса. Область подразделений и IP-допуск не менялись.

`CurrentUserService` реализует только `ICurrentUserDisplayService`. У него больше нет HTTP-зависимости, кэша автора и интерфейса `ICurrentUserService`. Проверки полномочий и повторная проверка области до возврата display DTO сохранены.

Legacy `AuditSaveChangesInterceptor` получает идентичность непосредственно через `ICurrentSession` при сохранении. Загрузка layout больше не нужна для определения автора. Анонимное техническое сохранение сохраняет fallback `system`. Сеанс сам по себе не является проверкой доступа: прикладные операции обязаны проверять permissions и область. Интерцептор намеренно не вызывает PermissionService, чтобы не запускать рекурсивные проверки политики и новые записи из аудита.

Синхронный SaveChanges поддерживается, если идентичность уже доступна. Если её получение ещё выполняется, он выдаёт явную ошибку с требованием SaveChangesAsync до изменения метаданных; блокирующего ожидания async-задачи или использования старого автора нет. При отмене асинхронного получения автора метаданные не изменяются.

Аудит контекстов на операцию (`UnitOfWorkFactory` с подтверждённым UserAccessSnapshot), явные авторы синхронизации и экспорта не заменяются legacy-интерцептором. Конфигурация подключения, схема и миграции не менялись.

## Проверки и границы

Сборка: 0 ошибок, 25 существующих предупреждений. Обычный runner: 18 777 проверок, включая 22 новые проверки. Новый набор использует настоящий pipeline EF с подавлением самой записи: проверяет приоритет circuit/HTTP, отсутствие устаревшего кэша, анонимный контекст, ошибки и отмену, асинхронный и синхронный аудит. Он сам не подтверждает запись в PostgreSQL.

Интеграционный runner `--postgres Guard/appsettings.json`: 19 555 проверок вместе с обычным набором. В отдельной временной localhost-БД проверены также реальные INSERT/UPDATE с новым интерцептором: автор без загрузки display, смена автора между сохранениями, защита CreatedBy/InsertedDate и UTC/Status. БД создана runner'ом и удалена в finally. Остальной набор проверяет в том числе отзыв security stamp, роли, область, блокировки, IP-допуск и HTTP-выдачу экспорта с обновлённой DI-регистрацией сеанса. Полноценный браузерный сценарий переподключения circuit в этой поставке не выполнялся.
