# Граница экспорта и настройки хранения

Дата: 16 октября 2026 года. Продолжение этапа 1 в `codex/architecture-ip-search`.

## Изменения

`ExportFilterCapture` находится в Web (`Components/Library`): преобразует дескрипторы
Radzen в независимый снимок `ExportFilter`. Потребители классификаторов,
подразделений, административных списков и архива используют этот адаптер.
Типы и JSON `ExportRequest`/`ExportFilter`, номера enum и версия схемы задания не менялись.

`ExportArchiveQuery` определяет неизменяемый набор разрешённых полей и типов
архива. `ExportFilterValidation` проверяет сериализованный фильтр без IQueryable,
EF, Radzen и сущностей: поля, стандартные операции, типы JSON, сложность
(глубина 16, максимум 100 узлов), отсутствие null-условий.
Пустой фильтр и пустая группа сохраняют поведение отсутствующего ограничения.
Произвольные Custom-операции, имена операций в виде числовых строк и строковые
операции над нестроковыми полями не поддерживаются. Обычный Capture сохраняет
имена стандартных операций, значения enum — JSON-числа, как и раньше.

Архив применяет независимую проверку до сохранения снимка в UI. Сервер повторяет
её перед SQL, а адаптер `ExportFilters.Apply` проверяет типы перед построением
выражения. UI больше не вызывает Apply на пустом IQueryable и не обращается к
конкретному `DataExportService`; набор ArchiveFields из реализации удалён.
Определения полей конструктора Radzen пока используют ExportJob, что допускается
на переходном этапе; результат таблицы остаётся DTO.

## Исправление групп и дат

Проверка локального календарного дня обнаружила прежний дефект: одиночная
вложенная группа без собственного Property могла пропускаться Radzen. Снимок
содержал правильные границы UTC, но сервер возвращал записи без этого ограничения.
Теперь сервер явно обходит AND/OR-группы и соединяет их предикаты. Для дат строятся
типизированные сравнения точных границ; DateTimeOffset нормализуется к UTC перед SQL.
Сравнения строк, списков и enum остаются на прежнем адаптере Radzen с регистронезависимым
сравнением. Пустые незаданные условия не превращаются в истинный член OR-группы.

Это намеренное исправление поведения: ранее пропущенные вложенные группы теперь
реально сужают выборку. Для сформированных ранее заданий структура JSON совместима;
проверен буквальный JSON версии 1. Миграция заданий или данных не требуется.
Полный архив реальных старых JSON-заданий не использовался.

## Хранение

`GetRetentionAsync` проецирует `ExportRetentionDto(Years, Version)` вместо сущности,
затем повторяет серверную проверку Root. При отсутствии настройки возвращает
3 года и Guid.Empty; создание настройки по-прежнему выполняет серверная операция.
Сохранение принимает явные Years/Version, проверяет диапазон 1–30, права и версию.
Аудит, EF concurrency token и применение нового срока только к новым заданиям сохранены.

Форма использует собственную RetentionForm и загруженную версию. После ошибки
загрузки сохранение недоступно, есть повторная загрузка. Во время сохранения
повторный запрос блокируется; закрытие отменяет операцию и исключает применение
позднего результата к диалогу. Общая оболочка EditEntity сохранена.

- Runner в режиме `--browser Guard/appsettings.json`: 1571 проверка, включая
  интеграции PostgreSQL, старый JSON, вложенные группы, enum, Guid, строки и списки,
  offset-даты, границы дня, ошибочные поля/значения, ограничения сложности,
  серверную пагинацию/сортировку, права и конкуренцию хранения, жизненный цикл формы.
- Существующие проверки обработки, preview, HTTP-выдачи, отзыва доступа, шифрования,
  сроков хранения и удаления истёкших артефактов также прошли.
- Дополнительно стенд выполнил 15 HTTP-проверок собственного пароля/logout.
- Браузер: автоматическая первая загрузка 10 строк, сортировка по автору,
  фильтр автора (10 → 2), независимость применённого фильтра от правок конструктора
  при обновлении, очистка (2 → 10), дата без записей (0) и дата создания (10),
  открытие и закрытие формы хранения с загруженным значением 4.
- В браузере не выполнялись сохранение срока и переход между страницами:
  срок проверен серверными/компонентными тестами, пагинация — SQL-интеграцией;
  все 10 записей стенда помещались на одну страницу. Статусы и иерархия в архиве
  не имеют отдельных переключателей и не добавлялись.
- Стенд работал на отдельной временной БД и с синтетическими данными. После
  проверки сервер остановлен, БД и временные файлы удалены. Обычный запуск приложения
  и изменение рабочих подключений не выполнялись.
- `git diff --check` — без ошибок.
