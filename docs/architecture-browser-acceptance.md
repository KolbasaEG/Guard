# Браузерная проверка архитектурного перехода

Дата: 17 октября 2026 года. База: `b17cec6` и описанные ниже UI-исправления.
Ветка: `codex/architecture-ip-search`.

## Стенд

Проверка выполнена встроенным браузером на localhost:5079 под синтетическим Root.
BrowserTestHost получает случайную временную PostgreSQL-БД от PostgresTests;
основное подключение и подключение логов дочернего приложения указывают только на неё.
Экспорты и ключи защиты размещаются в отдельном случайном временном каталоге.
Рабочие подключения и данные не менялись, новые миграции в рабочую БД не применялись.

Стенд дополнен 27 сотрудниками разных статусов, своим/дочерним/чужим подразделениями
и тремя IP этих подразделений. Существующий тестовый Root привязан к сотруднику своего
подразделения. Перед запуском браузерной части только в этой БД устанавливается ручной
режим управления и отключается расписание API, чтобы состояние предыдущих серверных
тестов не скрывало формы записи. Ранее созданные интеграционными тестами записи остаются:
это объясняет общие количества, превышающие 25 синтетических активных сотрудников.

Запуск из корня после изолированной сборки, при свободном порте 5079:

```powershell
$env:GUARD_TEST_APP_DLL = (Resolve-Path Guard/obj/search-contract-build/Guard.dll).Path
./scripts/Test-Guard.ps1 -Mode Browser -BinaryDirectory Guard/obj/search-contract-build
```

Это интерактивный runner: Enter останавливает дочернее приложение, удаляет его временный
каталог и затем временную БД. Не запускайте обычный Program ради проверки на неизвестном
подключении. Нормальный запуск приложения в Development выполняет seeding.

## Исправления по результатам проверки

1. В списке сотрудников статусы перекрывали кнопки на узкой панели. Добавлены локальные
   CSS и контейнер по образцу каталога IP: при ширине окна до 1200 px статусы занимают
   отдельную строку, оставаясь по центру всей панели; действия располагаются справа.
2. Аналитическая подпись сотрудников показывала «Только свои» при выборе «Весь персонал».
   Теперь подпись учитывает ShowAll. Серверная выборка уже соблюдала выбранный режим.
3. Светлая текстовая кнопка «Применить» сливалась со светлым фоном общего заголовка.
   В AnalitycsWrapper только Light/Text-кнопки заголовка получают тот же цвет, что заголовок.
   Проверено визуально и по вычисленному цвету: rgb(58, 71, 77) у кнопки и текста заголовка.
   Остальные стили кнопок не изменены.

## Автоматические проверки и ограничения

Сборка успешна: последняя инкрементальная — без предупреждений и ошибок;
пересборка Web показывала 21 существующее предупреждение, без ошибок.
Browser-режим повторно выполнил **4 711 unit + 21 073 integration = 25 784** проверки.
Дополнительно дочерний HTTP-host прошёл **20** проверок собственного пароля/выхода и
**70** локального Account: CSRF, ReturnUrl, удалённые маршруты, отказ 2FA с сохранением
флага и другие сценарии. Эти 90 проверок печатаются отдельно и не включены в 25 784.

Встроенный браузер не сообщил событие download за 15 секунд, хотя интерфейс подтвердил
«Файл передан сервером». Поэтому сохранение и содержимое фактически скачанного браузером
файла этим прогоном **не подтверждены**. Повторную одноразовую выдачу не выполняли.
Формирование файлов и HTTP-выдача покрыты отдельными автоматическими проверками;
синтетический экспорт 100 тыс. строк измерен в [отчёте индекса](architecture-personal-pagination-index.md).

Это выборочная проверка ключевых сценариев, а не полная пользовательская приёмка.
Не проверены вручную все формы, смена ролей/permissions, все сортировки/фильтры всех
списков, полный набор размеров окна и работа под обычной учётной записью; серверные
ограничения доступа покрываются интеграционными проверками. Внешняя доставка SIEM
на стенде не проверялась: адрес принудительно указывает на закрытый localhost:9,
поэтому сообщения об отказе соединения этого sink ожидаемы.

Ветка остаётся на пользовательской проверке. Слияние, применение миграций, публикация
и push этим прогоном не выполнялись.
