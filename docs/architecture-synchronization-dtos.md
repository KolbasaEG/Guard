# DTO синхронизации

Дата: 16 октября 2026 года. Продолжение этапа 1 в `codex/architecture-ip-search`.

## Результат

`ISynchronizationService` больше не возвращает сущности БД. Обзор содержит
`SynchronizationSettingsDto` и `SynchronizationRunDto`; история и результат
прямого запуска либо постановки в очередь используют тот же DTO запуска.
Снимки — sealed record с init-свойствами; коллекция истории доступна только для чтения.

Настройки читаются через SQL-проекцию: в результате есть версия, режим,
параметры источника, расписание, подтверждение полноты, даты актуальности и
восстановления. Вместо пароля возвращается только `HasApiPassword`. В DTO нет
ни открытого, ни защищённого пароля. Не требуется обнулять поле сущности перед
возвратом; защищённый пароль не материализуется для отображения обзора.

История и последняя попытка проецируются до материализации. Сортировка общая:
`StartedAt DESC, Id DESC`; история ограничена 20 строками. DTO сохраняет область,
признак расписания, дату выборки, времена, статус, фазу, все счётчики и сообщение
об ошибке. Автор и ожидаемая версия настроек очереди остаются серверными полями.
Результат записи преобразуется после её завершения.

Страница настроек, история и панель состояния переведены на DTO. Форма ввода
остаётся отдельной моделью Web. Сохранение по-прежнему принимает явные скалярные
параметры, включая ожидаемую версию и новый пароль; сущность из UI не принимается.
Проверка смены источника использует общую функцию со строковыми параметрами,
без зависимости UI от сущности настроек. Пустой пароль сохраняет прежний секрет.

## Сохранённые границы

Проверки Root, optimistic concurrency, подтверждение полного снимка, транзакции,
advisory locks, durable queue, повторная проверка прав worker, расписание,
recovery и обработка снимка сохранены. Runner/worker продолжают работать с
внутренними сущностями. Регистрация DI, схема БД и настройки подключения не менялись.

Это разделение контрактов, а не завершение аудита атомарности и доверенного
исполнителя этапа 2. Повторная проверка доступа после чтения обзора/истории не
добавлялась. Перечисления режима и статуса пока сохраняют прежний namespace;
перенос их расположения относится к последующему разделению сборок.
