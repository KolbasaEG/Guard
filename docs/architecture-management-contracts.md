# Контракты управления для UI

Дата: 16 октября 2026 года. Ветка: `codex/architecture-ip-search`. Продолжение этапа 1 после поставки Account `22e8e94`.

Списки и формы IP, подразделений и классификаторов использовали DTO, но получали через DI широкие интерфейсы с IQueryable и сущностями. Список пользователей дополнительно получал IdentityResult при блокировке. Теперь эти потребители используют независимые контракты; выполнение запросов, проверки доступа и транзакции остаются в существующих реализациях.

## Изменения

| Потребители | Контракт | Реализация |
| --- | --- | --- |
| IP: Index, Add, Edit | IIpAddressManagementService | IpAddressService |
| Подразделения: Index, Add, Edit, Move | ISubdivisionManagementService | SubdivisionService |
| Классификаторы: Index, Add, Edit | IClassifierManagementService | ClassifierService |
| Пользователи: Index | IUserListService | SecurityService |

Контракты содержат DTO, параметры поиска, идентификаторы, версии и CancellationToken. Методы статусов и переноса сохраняют прежние параметры и правила. Новый SetUserLockoutAsync проверяет IdentityResult существующей операции и сообщает об ошибке исключением; UI показывает успех только после завершения. Сохраняются запрет блокировки Root, серверная область доступа, обновление security stamp, аудит и транзакция записи. Новая модель конкуренции здесь не вводится.

Старые IIpAddressService, ISubdivisionService, IClassifierService и ISecurityService наследуют соответствующие новые интерфейсы. Их API с сущностями и query-делегатами сохранён для совместимости серверного кода и тестов. Scrutor регистрирует новые интерфейсы через AsImplementedInterfaces без дополнительных регистраций в Program. Разделение интерфейсов не меняет существующий scoped lifetime реализаций и само по себе не решает вопрос времени жизни контекстов.

## Оставшиеся legacy-потребители

Поиск выполнен по всему Guard и Guard.IpRules.Tests, включая Shared и Program, а не только Components. Таблица фиксирует группы потребителей; это не доказательство безопасности каждого старого метода.

| Контракт | Оставшиеся потребители и решение |
| --- | --- |
| ISecurityService | SecurityService, регистрации и интеграционные тесты; Shared/DialogInfo всё ещё получает ApplicationUser через GetUserByIdAsync в резервном пути BaseEntity. Единственные найденные вызовы диалога передают IP/Subdivision DTO и обходят этот путь. Следующая поставка — убрать резервную зависимость с сохранением сведений об авторе |
| IIpAddressService | SecurityService.QueryIpAddressesAsync, собственные методы чтения IpAddressService, проверки доступа/IP и тестовые proxy. Сохранить в серверной части до отдельной ревизии удаления |
| ISubdivisionService | Реализация, регистрации тестовой среды, интеграционные тесты и proxy форм/списка. В Components больше не внедряется |
| IClassifierService | Shared/DialogInfo имеет неиспользуемое внедрение; тесты и proxy. Удалить внедрение вместе с очисткой диалога; остальной legacy API пока совместим |
| IPersonalService | PersonalService и тестовые регистрации/proxy/интеграционные сценарии. UI ранее переведён на отдельные контракты поиска, просмотра, редактора и статусов |
| IApplicationRoleService | ApplicationRoleService; поиск UI уже через IRoleSearchService. Старые методы с ApplicationRole не переносить в будущий Application |
| ILogService | LogService и явные DI-регистрации Program; UI использует ILogSearchService. Query-API относится к инфраструктуре |

IdentityRevalidatingAuthenticationStateProvider остаётся техническим адаптером Web. Связь Personal.User с Identity остаётся отдельным вопросом выделения Domain. Наличие узких контрактов не означает завершения этапа 1 и не разрешает механически переносить весь каталог Services в Application.

## Проверка

- Сборка Guard.slnx с отдельным OutputPath и UseAppHost=false: 0 ошибок, 34 прежних предупреждения. Рабочий запущенный процесс не останавливался ради сборки.
- Актуальный Guard.IpRules.Tests.dll: **1761 проверка**, включая временную изолированную PostgreSQL-БД. Проверки блокировки/разблокировки и запрета блокировки Root используют новый контракт; обычный менеджер также не может блокировать Root через него.

UserSearchUiTests работает с proxy только IUserListService, сохраняя проверки отмены, позднего ответа и очистки при ошибке.
- Изолированный HTTP-хост: 20 проверок смены пароля/logout и 70 локального Account. Дополнительное аутентифицированное SSR-открытие /users, /ip, /subdivisions, /classifiers: HTTP 200 без перенаправления на вход.

Ручная интерактивная проверка фильтров, сортировки, пагинации и диалогов в браузере в этой поставке не выполнялась.
