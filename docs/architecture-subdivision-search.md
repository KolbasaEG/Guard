## Изменение

Список подразделений вызывает `ISubdivisionService.SearchAsync(SubdivisionSearchRequest)`
и получает `SubdivisionSearchResult` с Items и Count. Из компонента удалены EF,
query-делегат, SQL-проекция и отдельное получение собственного пути подразделения.
Старые методы сервиса сохранены для ещё не перенесённых карточек и потребителей.

Сервис получает актуальные permissions и серверную область доступа, читает
собственный Path сотрудника из БД, затем применяет область, статус, выбранную
иерархию, независимый фильтр, Count, сортировку, Skip/Take и SQL-проекцию DTO.
Версия записи остаётся в DTO для существующих операций записи. Размер страницы
ограничен 1–100. Root может выбрать все подразделения; при отключении этого режима
его отображение тоже ограничивается собственным подразделением/потомками.
Отсутствующий или некорректный Path возвращает пустую собственную область.

Чтение требует Subdivisions.Read, архив дополнительно ReadArchive, удалённые
записи доступны только Root. Прямой запрос запрещённого режима отклоняется;
ранее репозиторий исключал такие записи из произвольного запроса. До возврата
повторно проверяются permissions, пользователь, Root, множество подразделений
и собственный Path. При изменении доступа результат отклоняется.

`SubdivisionSearchQuery` строит выражения без Radzen и Dynamic LINQ. Разрешены
только прежние 15 полей, явно проверяются операции и типы значений. Поддерживаются
строки, строковые IN/NOT IN, bool, int, double, Guid и даты UTC. Сложность фильтра
ограничена 16 уровнями/100 узлами, строкового списка — 1024 значениями.
Сортировка ограничена разрешёнными полями и направлениями; Id обеспечивает
стабильную пагинацию. По умолчанию: InsertedDate desc, Id asc.

Web-адаптер `SubdivisionListQuery` сохраняет снимок условий, проверяет сложность
до рекурсивного преобразования и использует прежнее преобразование локальной
даты браузера в UTC/диапазон дня. Список и экспорт используют один снимок
и общий серверный построитель. Контракт сохранённых запросов экспорта не меняется.
Изменение конструктора до «Применить» не затрагивает сортировку и обновление.

Сохранена интеграция с подтверждением загрузки после синхронизации. Предыдущие
запросы отменяются, поздний ответ не заменяет актуальную страницу. Повторный
Dispose теперь безопасен — этот случай обнаружен проверкой жизненного цикла.
Схема БД, миграции, перенос дерева и операции записи не изменены.

## Оставшиеся границы

На момент этой поставки карточки/варианты выбора использовали сущности и прежние
методы. Их переход выполнен в [четвёртой поставке](architecture-subdivision-dialogs.md).
Конструктор фильтра списка тоже сохраняет Subdivision как модель полей на
переходном этапе. Web-преобразование снимка пока использует прежний Capture
из ExportFilters; устранение оставшихся зависимостей Radzen в старом экспортном
коде относится к подготовке физического разделения проектов.

Count и страница читаются отдельными SQL-командами без RepeatableRead: конкурентное
изменение данных между ними возможно. Полная история миграций, браузер оператора,
нагрузка и перенос ветви во время поиска этой поставкой отдельно не проверялись.
Права оператора и область проверены на PostgreSQL. Рабочие подключения, данные
и настройки не изменены; слияние, push и развёртывание не выполнялись.

Следующий объём: DTO карточек и вариантов подразделений, затем серверный поиск
классификаторов и оставшихся областей согласно общему плану.
