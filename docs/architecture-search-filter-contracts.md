# Независимые правила фильтров пользователей, ролей и журналов

Дата: 16 октября 2026 года. Ветка: `codex/architecture-ip-search`. База: `ad22f19`.

## Изменения

В `SearchFilterValidation.cs` выделены независимый валидатор сериализованного `ExportFilter` и описания полей `UserSearchFilter`, `RoleSearchFilter`, `LogSearchFilter`. Они используют только BCL и контракт фильтра, без EF, сущностей, Identity, Radzen и построения выражений. Наборы полей и словари типов неизменяемы.

Web обращается к этим описаниям при сохранении снимка по кнопке «Применить». Серверные `UserSearchQuery.ValidateFilter`, `RoleSearchQuery.ValidateFilter`, `LogSearchQuery.ValidateFilter` делегируют проверку тем же правилам; существующие сервисы продолжают вызывать их до обращения к данным. Сигнатуры query API сохранены. `RestrictedSearchQuery` продолжает самостоятельно защищать построение выражений и выполнять прежнюю фильтрацию и сортировку. Его отдельный метод проверки через построение предиката удалён как неиспользуемый.

Сохранены различия со стандартным валидатором экспорта: строго UTC, запрет упорядочивающих операций для bool/Guid, регистронезависимые строковые сравнения и регистрозависимые `In/NotIn`, пустые значения, поведение null и пустых групп. Операции проверки null/пустоты игнорируют переданное значение, как прежде. Пределы — глубина 16, всего 100 узлов с учётом корня, 1024 элемента строкового списка. Неизвестные поля и операции отклоняются. Преобразование календарных дат остаётся в Web.
