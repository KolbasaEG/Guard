# Классификаторы: серверный поиск и DTO форм

Пятая поставка этапа 1 [плана перехода](architecture-transition-plan.md).
Ветка: `codex/architecture-ip-search`. Слияние требует проверки пользователя.

## Изменения

- `IClassifierService.SearchAsync(ClassifierSearchRequest)` возвращает `Items + Count`.
  Права чтения проверяются до запроса и перед возвратом результата, включая смену пользователя и permissions.
- `ClassifierSearchQuery` проверяет семь поддерживаемых полей, типы и операции фильтра,
  глубину до 16 и число узлов до 100. Даты принимаются в UTC. Сортировка строится через
  типизированные выражения, по умолчанию Type/Code/Id; Id стабилизирует страницы.
- Сервис использует существующий `IReadRepository.QueryAsync`: отдельный контекст,
  SQL-фильтр, Count до страницы, сортировка, Skip/Take, проекция DTO до материализации.
- `GetDetailsAsync` проецирует `ClassifierDetailsDto`, включая версию и время обновления.
  Справочник общий для организации, активные и неактивные записи доступны с Classifiers.Read.
- Web преобразует Radzen-условия в независимый снимок через `ClassifierListQuery`.
  Изменение конструктора до «Применить» не меняет действующий запрос.
  В списке больше нет EF, Dynamic LINQ и query-делегатов.
- Add/Edit используют DTO и отдельный снимок команды. Сохранение блокирует повторную
  отправку; закрытие отменяет запрос. Поздние ответы не меняют следующую форму.
- Предварительная проверка уникальности Type/Code перенесена из форм в сервис записи;
  уникальное ограничение БД сохраняет защиту от гонки. Управление API, permissions,
  версии и обработка ошибок UoW сохранены.

## Затронутые области

`Core/6-Services`: контракт, реализация ClassifierService, ClassifierSearchQuery,
DTOs/ClassifierDetailsDto. `Components/Pages/Classifiers`: список, преобразователь
фильтра, формы. `Guard.IpRules.Tests`: ClassifierIntegrationTests, ClassifierUiTests,
регистрация проверок и синтетические данные временного браузерного стенда.

## Проверки

- Сборка .NET/C#/Razor успешна; существующие предупреждения проекта сохраняются.
- Автоматические проверки: SQL-фильтры и сортировки, Count/пагинация, DTO карточки,
  права чтения/записи, смена пользователя до возврата, отмена, неверные параметры,
  дубликаты, конфликт версии, независимость снимка фильтра, поздние ответы и повторная отправка.
- PostgreSQL проверяется только на создаваемой runner временной БД; подключения
  приложения и реальная БД не изменяются. Временная БД удаляется при завершении runner.
- Runner: 1375 проверок и 15 HTTP-проверок успешно выполнены. В браузере проверены
  первая загрузка, две страницы, сортировка, применение/очистка фильтра, независимость
  его снимка, просмотр в режиме API, создание, изменение значения, смена активности
  и закрытие форм. Синтетические записи удалены вместе с временной БД.

## Ограничения

Старые entity/query-методы сервиса остаются для ещё не перенесённых потребителей.
Модель Classifier используется в Web только как описание полей конструктора фильтра.
Новых режимов статуса, переключателей иерархии, миграций или пакетов нет.
Физическое выделение проектов и единый механизм построения фильтров нескольких
областей в эту поставку не входят. Конкурентная вставка одинакового Type/Code
отдельным параллельным тестом этой поставки не проверялась.

При браузерной проверке воспроизведено существующее ограничение: изменение пары
Type/Code через Edit завершается ошибкой. Эта пара является альтернативным ключом
EF (HasPrincipalKey в связях справочников). Изменение значения/наименования/активности
сохраняется. Перенос зависимых ссылок при смене ключа требует отдельного решения;
данная поставка поведение этой операции не меняет.
