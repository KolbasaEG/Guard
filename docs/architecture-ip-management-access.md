# IP-полномочия в Application

Дата: 17 октября 2026 года. База: `7d30cbf`, ветка `codex/architecture-ip-search`.

`IpManagementAccessService` перенесён из Infrastructure в Application без изменения содержимого и namespace. Он зависит только от независимых IPermissionService и IDataAccessScopeService. Новых портов, пакетов и зависимостей проектов нет.

Сохраняется порядок: RequireAsync с IpAddresses.Read для чтения либо IpAddresses.Manage для записи → GetAsync серверной области → IpManagementScope с доверенным UserId, IsRoot и SubdivisionIds. Проверка полномочия выполняется и для Root; пустая область не расширяется. Отказы и отмена любого этапа передаются вызывающему коду. Сервис не владеет контекстом/транзакцией и не заменяет проверки конкретной записи в IP-операциях Infrastructure.

В AddGuardApplication добавлена явная scoped-регистрация. Infrastructure сканирует только собственную сборку и после переноса больше не регистрирует этот сервис. Число независимых решений в композиции Application выросло с трёх до четырёх; контрактов по-прежнему 35. Сохранены существующие типы, lifetime и потребители.

## Проверки

- 38 новых unit-проверок: read/manage, Root/обычный пользователь, пустая/ограниченная область, доверенный исполнитель и token; ошибки полномочий не запускают чтение области; ошибки чтения не становятся успешным пустым результатом; ожидающее разрешение останавливает следующий этап; отмена до и между этапами сохраняется.
- DI проверяется для Development/Production при общей и раздельной композиции в обратном порядке: Infrastructure не регистрирует контракт, итоговая регистрация единственная scoped, граф разрешается, экземпляры общие внутри scope и разные между scopes.
- Проверка границ сборок подтверждает принадлежность реализации Application и отсутствие дубликатов. Независимая сборка UnitTests успешно запускает 1 941 проверку с Domain/Application.
- Сборка решения: 0 ошибок; первая полная компиляция — 25 прежних предупреждений, повторная — без предупреждений.
- Общий скрипт с PostgreSQL: **1 941 unit + 21 021 integration = 22 962** проверки, код 0; на 51 больше предыдущих 22 911. Временная изолированная БД удалена.

Рабочие данные, подключения, схема и UI не менялись. Приложение, браузер, нагрузочный режим и публикация не запускались.

## Следующий участок

Сверить независимые данные для AccountPolicyRules: сейчас правила срока пароля и неактивности принимают ApplicationUser. Отделить необходимые поля от Identity, сохранив даты активации политики, MustChangePassword, исключение Root из блокировки по неактивности и существующие граничные даты. Саму запись блокировки, Identity и транзакции оставить в инфраструктурной операции. Остальные открытые участки этапов 1–2 перечислены в [предыдущей сверке](architecture-status-rules.md); этот перенос закрывает её строку IP-полномочий.
