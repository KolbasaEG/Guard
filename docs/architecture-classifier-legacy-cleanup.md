# Удаление legacy-контракта классификаторов

Актуальное продолжение: [IPersonalService также удалён](architecture-personal-legacy-cleanup.md); осталось три legacy-интерфейса. Следующий участок — ISubdivisionService. Ниже сохранён отчёт о срезе `51348ce`.

Ветка: `codex/architecture-ip-search`. База: `268c5e0`. IClassifierService удалён; ClassifierService реализует только IClassifierManagementService из Application. В Infrastructure остаются четыре legacy-интерфейса. Этапы 1–2 целиком не закрыты.

## Аудит и изменения

Производственный UI уже использовал DTO-контракт. Старый интерфейс оставался в двух наборах UI-прокси, явной тестовой регистрации DI и реестрах границ. Эти потребители переведены на IClassifierManagementService; PostgreSQL-проверки также работают через этот интерфейс.

Шесть старых методов чтения не имели вызывающего кода в производственных и тестовых проектах: QueryClassifiersAsync, GetByIdAsync, GetByTypeAsync, GetByClassifierNameAsync, GetAllAsync, IsCodeUniqueInTypeAsync. Они удалены. Проверка уникальности при записи через RequireUniqueCodeAsync сохранена.

CreateAsync(Classifier) и UpdateAsync(Classifier) вызываются DTO-методами внутри реализации, поэтому сохранены как private. Их тела, валидация, permissions, проверка локального режима, версия, время UTC, аудит и владение контекстом не изменены. Остальные тела методов также сохранены. Новых обёрток и проектов нет.

Scrutor регистрирует узкий контракт напрямую. Проверки общей и раздельной композиции в Development/Production подтверждают единственную scoped-регистрацию и изоляцию между scopes. Реестр сборок проверяет отсутствие IClassifierService и публичных legacy-методов реализации.

Удаление публичного CLR-контракта и старых методов нарушает совместимость внешних потребителей, если они существуют. Поиск внутри репозитория не доказывает их отсутствие вне репозитория.

## Проверки

- Сборка решения: 0 ошибок, 25 прежних предупреждений.
- Полный Test-Guard.ps1 с PostgreSQL: **4 711 unit + 20 863 integration = 25 574**, код 0. Временная БД удалена.
- Через DTO-контракт дополнительно проверены отказ read-only пользователю в обновлении, смене активности и удалении; сохранность записи после отказов; успешная смена активности; конфликт устаревшей версии при смене активности и удалении; сохранность актуальной записи; удаление по актуальной версии и исключение из поиска.
- Существующие проверки SQL-поиска, DTO, уникальности, смены исполнителя, отмены, форм и обновления списка после синхронизации сохранены. Проверки границ и DI обновлены; итоговый счётчик вырос на 14 с учётом изменения динамического инвентаря.

Рабочая БД, настройки, схема, миграции и UI не изменены. Приложение, браузер и нагрузочный стенд не запускались.
