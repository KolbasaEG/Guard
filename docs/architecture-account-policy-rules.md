# Правила политики аккаунтов в Application

Дата: 17 октября 2026 года. База: `1168b99`, ветка `codex/architecture-ip-search`.

`AccountPolicyRules` перенесён из Infrastructure в Application. Полное имя типа и вычисления сохранены; вместо Identity-модели `ApplicationUser` методы принимают `AccountPolicyUserState`: неизменяемый снимок пяти полей (создание, смена пароля, активность, разблокировка и обязательная смена пароля). Новых интерфейсов, пакетов и зависимостей проектов нет. Application по-прежнему зависит только от Domain и BCL, содержит 35 сервисных контрактов.

В Infrastructure остаётся внутреннее преобразование `ApplicationUser` в снимок. `AccountPolicyService` создаёт снимок непосредственно при каждой проверке, включая повторную проверку после чтения под advisory lock. Транзакции, повторное чтение пользователя/политики/Root, сохранение блокировки, stamps, аудит и уведомления остаются в прежней операции. SQL предварительного отбора в SweepAsync не изменён; окончательная проверка выполняется через CheckAsync как прежде.

Сохраняются обязательная смена пароля даже при отключённом сроке, приоритет явной даты смены пароля над датой включения политики, старт legacy-периода от более поздней даты создания/включения. Для неактивности учитываются активность (либо создание при её отсутствии), разблокировка и включение политики. Root освобождён только от неактивности. Равенство крайнему сроку означает истечение; сравнение выполняется по моменту времени.

## Проверки

- Сборка решения: 0 ошибок, 25 прежних предупреждений.
- Добавлено 1 765 независимых проверок: комбинации отсутствующих/ранних/поздних дат, переключатели, Root, граница ±1 tick, смещения времени и пределы настроек политики.

- Полный скрипт с временной PostgreSQL-БД: **3 706 unit + 21 026 integration = 24 732** проверки, код 0. Временная БД очищена штатным runner.
- Независимая сборка/запуск UnitTests: 0 ошибок и предупреждений, 3 706 проверок. Из производственных сборок в каталоге только Domain и Application.
- Рабочие БД, подключения, миграции, Account UI и поведение 2FA не менялись. Браузерные и нагрузочные проверки, публикация в этом участке не выполнялись.
