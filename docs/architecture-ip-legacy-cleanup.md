# Удаление legacy-контракта IP

Дата: 17 октября 2026 года. Ветка: `codex/architecture-ip-search`. База: `6bd8df1`.

## Выполненный участок

Удалён IIpAddressService. IpAddressService реализует только независимый IIpAddressManagementService из Application: поиск, карточка, варианты подразделений, DTO-создание/редактирование и команды жизненного цикла. UI уже использовал этот контракт и не менялся. В Infrastructure остался один legacy-интерфейс — ISecurityService.

| Старый метод или зависимость | Решение после сверки потребителей |
| --- | --- |
| SecurityService.QueryIpAddressesAsync и параметр IIpAddressService | Прокси существовал, но вызовов в репозитории не было. Удалены метод, объявление в ISecurityService и параметр конструктора; атомарные Identity-операции не менялись |
| IpAddressService.QueryIpAddressesAsync | Удалён. SQL-проверки IpIndexTests выполняют прежние выражения напрямую над временным контекстом; проверки серверной области, пагинации и повторной проверки доступа остаются на SearchAsync |
| GetByIdAsync | Удалён. Тесты канонизации и сокрытия общего адреса вызывают GetDetailsAsync |
| GetAllActiveAsync | Удалён. Тесты используют SearchAsync: для оператора IncludeChildren, для Root явный AllSubdivisions |
| GetBySubdivisionIdAsync и IsIpUniqueAsync | Удалены: внешних вызовов в репозитории нет |
| CreateAsync(IpAddress), UpdateAsync(IpAddress) | Удалены оболочки над DTO. Проверки каталога, назначений, IPv4/IPv6 и конкурентных дублей переведены на CreateIpAddressDto |

Внутренний IsUniqueAsync сохранён: WriteAsync продолжает проверять канонические дубли под той же advisory lock. Тела сохранённых методов, транзакции, права, область, статусы, аудит, отмена и блокировка каталога не изменены. Алгоритм проверки уникальности по-прежнему читает все строки адресов; его оптимизация на объёме 10 млн IP требует отдельного изменения и нагрузочной проверки.

Тестовые прокси форм и списка, ручная DI-композиция и фикстуры переведены на узкий контракт. Обновлены вызовы конструктора SecurityService, включая проверки rollback Identity. Проверки сборок требуют отсутствия IIpAddressService, точного соответствия публичных методов IpAddressService DTO-контракту и отсутствия IP-прокси/зависимости каталога у SecurityService. DI проверяет единственную scoped-регистрацию и изоляцию scopes в общей/раздельной композиции, Development/Production.

Дополнительно проверяются отказы DTO-создания и всех пяти команд статуса для read-only пользователя: каталог не пополняется, поля, статус и аудит существующей записи сохраняются.

Удаление публичных CLR-методов и параметра конструктора нарушает совместимость внешних потребителей, если они существуют. Поиск внутри репозитория не доказывает их отсутствие за его пределами.

## Проверки и ограничения

- Итоговая инкрементальная сборка: 0 ошибок, 0 предупреждений. При первой полной пересборке были 25 прежних предупреждений Web; они остаются в исходниках.
- Полный Test-Guard.ps1 с PostgreSQL: **4 711 unit + 20 927 integration = 25 638**, код 0. Временная изолированная БД удалена.
- Сохранены проверки доступа, DTO, форм/списка, фильтров, назначений, конкурентных дублей, отмены и отката Identity. Добавлены семь проверок запрета IP-записи и три проверки границ; с учётом восьми DI-проверок и сокращения динамического инвентаря счётчик вырос на 13.

Рабочая БД, подключения, схема, миграции и UI не изменены. Приложение, браузер, публикация и нагрузочный стенд не запускались. Четыре производственных и два тестовых проекта сохраняются; этапы 1–2 целиком не закрыты.

Следующий участок — пооперационный аудит ISecurityService: удалить неиспользуемые entity/query-оболочки, сохранить независимые DTO-контракты и атомарность обязательных IdentityResult, транзакций, аудита и уведомлений. Отдельно остаются размещение HTTP/workers, неопределённый исход commit и гарантированная доставка аудита.
