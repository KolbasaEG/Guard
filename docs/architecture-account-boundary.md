# Account: локальный вход, выход и смена пароля

Дата: 16 октября 2026 года. Продолжение этапа 1 в ветке `codex/architecture-ip-search`.

## Согласованный объём и текущее состояние

Пользователь подтвердил: нужны только локальный вход, выход и смена своего пароля. Самостоятельная регистрация, восстановление по email, внешние провайдеры, 2FA и passkey исключены. Для существующего аккаунта с включённой 2FA пользователь отдельно выбрал отказ во входе с сообщением обратиться к администратору; флаг 2FA и ключи сохраняются.

| Сценарий | Реализация |
| --- | --- |
| `/Account/Login` | Static SSR → ILocalAccountService; независимый LocalSignInStatus; поиск по email, lockout, IP-проверка и аудит остаются на сервере |
| GET/POST `/Account/Logout` | GET только подтверждает; POST проверяет antiforgery → ILocalAccountService.SignOutAsync → LocalRedirect; выход доступен при MustChangePassword |
| `/Account/Manage/ChangePassword` и POST `/Account/ChangeOwnPassword` | Общий IOwnPasswordService с независимым результатом; текущий пользователь определяется сервером |
| Аккаунт без локального пароля | Сообщение об обращении к администратору и кнопка выхода; формы установки пароля нет |
| Register/ConfirmEmail/Forgot/ResetPassword/ResendEmailConfirmation и страницы подтверждения | Маршруты удалены; фиктивный отправитель удалён |
| ExternalLogin, LoginWith2fa/RecoveryCode, управление внешними входами, passkey и 2FA | Страницы, endpoints и JS удалены; скрипт исключён из App.razor |
| Manage/Profile, Email, PersonalData, DeletePersonalData | Самостоятельное управление удалено вместе с ManageLayout/ManageNavMenu; административный раздел пользователей сохранён |

Удалены сами обработчики и маршруты, а не только ссылки. Таблицы Identity, миграции, флаги защиты, ключи и существующие данные не изменены. Из middleware и AccessStateProvider убрано исключение для удалённого SetPassword. Технический провайдер перепроверки аутентификации остаётся интеграцией Web с Identity.

## Контракт локального входа и выхода

`ILocalAccountService` принимает email, пароль, rememberMe и CancellationToken; возвращает LocalSignInStatus без ApplicationUser, SignInResult или HttpContext. Пароль передаётся скалярным параметром, не помещается в record и не логируется. Реализация `LocalAccountService` зарегистрирована scoped существующим Scrutor-сканированием. Она работает только в HTTP-запросе, использует существующие PolicyUserManager/IpRestrictedSignInManager и IAuditService. UI управляет формой и переходами; endpoint отвечает за CSRF и HTTP-ответ.

Email проверяется сервером на заполненность и обрезается по краям; поиск выполняется FindByEmailAsync, потому что UserName может отличаться. Отказы по паролю продолжают учитываться в lockout. Для аккаунта с TwoFactorEnabled вызывается только CheckPasswordSignInAsync: успешная проверка возвращает RequiresTwoFactor и аудит отказа, основная и промежуточная cookie не выдаются. Cookie запомненного устройства не позволяет пройти этот путь. При неверном пароле, блокировке или запрещённом IP сохраняется соответствующий отказ Identity. Уже открытые сессии автоматически не отзываются этим изменением.

RequestAborted передаётся в операции; отмена проверяется перед обращением к Identity и перед действием входа. API менеджеров не принимает отдельного CancellationToken. После завершённого изменения cookie дополнительная отмена не вставляется перед аудитом. HTTP sign-out и доставка аудита не являются единой транзакцией.

`AccountReturnUrl.Normalize` используется входом, POST выхода и ссылкой отмены: допускает локальные относительные пути, отбрасывает внешний адрес, `//`, обратные слеши и управляющие символы, по умолчанию возвращает `/`. Русские ошибки StatusMessage отображаются как alert-danger.

## Контракт смены пароля

`IOwnPasswordService` не использует ApplicationUser, IdentityResult, UserManager или HttpContext в сигнатурах. Состояние чтения — MissingUser/NoPassword/Ready; запись возвращает Succeeded/Unauthorized/Rejected и сообщение отказа. Пароли передаются скалярными параметрами, не помещаются в DTO/record с автоматически генерируемым ToString и не логируются.

`Core/Identity/OwnPasswordService` — серверный адаптер, зарегистрированный scoped существующим Scrutor-сканированием по суффиксу Service. Исполнитель берётся из текущего аутентифицированного HTTP-запроса; идентификатор пользователя из формы не принимается. Сервис предназначен для Static SSR/HTTP, а не длительного интерактивного circuit.

Сервис проверяет заполнение и подтверждение пароля, вызывает существующий PolicyUserManager, проверяет IdentityResult и только после успеха обновляет cookie через действующий SignInManager. Сохраняются парольная политика, запрет заблокированной учётной записи/повторного пароля, изменение security stamp, PasswordChangedAtUtc, MustChangePassword, аудит и IP-проверка при обновлении cookie. Endpoint отвечает за antiforgery, чтение HTTP-формы и преобразование результата в HTTP; Razor-страница — за отображение и переходы. Обе точки используют одну операцию.

CancellationToken проверяется перед чтением и изменением, HTTP-потребители передают RequestAborted. API UserManager/SignInManager не принимает отдельный token. После успешной записи намеренно нет дополнительной проверки отмены перед обновлением cookie. Смена пароля в БД и выдача cookie не являются одной транзакцией: сбой обновления cookie не откатывает уже сохранённый пароль; это прежнее ограничение Identity, успех при исключении не возвращается.

Схема БД, cookie scheme, конфигурация и рабочие подключения не изменены. Нормальный запуск приложения для проверки не используется.
