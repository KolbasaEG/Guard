# Очистка query API библиотеки UI

Дата: 16 октября 2026 года. Ветка: `codex/architecture-ip-search`. Продолжение `d47e198`.

## Изменения

Из `Guard/Components/Library/EntityListQuery.cs` удалены `Capture`, `Sort`, построитель выражений и вспомогательный visitor, а также импорты Expressions и Dynamic LINQ. Поиск по C#/Razor в Guard и Guard.IpRules.Tests до изменения нашёл вызовы этих методов только в RefactorTests. Действующие потребители Snapshot — AdministrationListQuery, SubdivisionListQuery и ClassifierListQuery — сохранены.

Snapshot продолжает копировать условия и коллекции значений, проверять разрешённые поля и преобразовывать даты из часового пояса браузера в UTC. Ограничения сложности проверяются вызывающими адаптерами до рекурсивного преобразования. Серверные проверки полей и операций сохранены.

`Guard.IpRules.Tests/RefactorTests.cs` теперь проверяет действующие пути:

- SubdivisionListQuery → независимый ExportFilter → SubdivisionSearchQuery: снимок не меняется при редактировании конструктора.
- UserListQuery с UserFilterFields → UserSearchQuery: календарный день включает начало и исключает следующую локальную полночь; GreaterThan для даты начинается со следующей полуночи. Проверена генерация PostgreSQL SQL без подключения к БД.
- AdministrationListQuery с LogFilterFields → LogSearchQuery: изменение исходной коллекции выбранных уровней не меняет применённый фильтр.
- SubdivisionSearchQuery.Sort: направление сортировки и отказ для неподдерживаемого поля.

UI больше не содержит прежнего универсального построителя IQueryable в EntityListQuery. Это не означает завершения разделения Web и серверных реализаций: адаптеры ещё обращаются к наборам полей и ValidateFilter серверных классов поиска.
