# Удаление legacy-контракта подразделений

Ветка: `codex/architecture-ip-search`. База: `3b88377`. ISubdivisionService удалён; SubdivisionService реализует только ISubdivisionManagementService из Application. Остались два legacy-интерфейса: IIpAddressService и ISecurityService. Этапы 1–2 целиком не закрыты.

## Аудит и изменения

Производственных потребителей старого интерфейса вне реализации нет. Тестовые регистрации, прокси форм и списка, проверки отката и конкурентных переносов переведены на существующий DTO-контракт.

| Старый метод | Решение |
| --- | --- |
| GetOwnSubdivisionPathAsync | Вызывающего кода нет; удалён вместе с невостребованной веткой тестового прокси |
| QuerySubdivisionsAsync | Потребителей нет; удалён |
| GetByIdAsync | Нужен внутри UpdateFromDtoAsync; сохранён как private, включая прежние Include и защиту ReadRepository |
| GetAllActiveAsync | Только проверка области доступа; она переведена на SearchAsync с IncludeChildren и без полного доступа Root |
| GetByParentIdAsync | Потребителей нет; удалён |
| GetOrganTypesAsync, GetClassifiersByTypeAsync | Потребителей нет; редакторы используют GetEditorOptionsAsync; удалены |
| CreateAsync(Subdivision), UpdateAsync(Subdivision) | Вызываются DTO-операциями; сохранены как private. Проверка чужого подразделения переведена на UpdateFromDtoAsync |

Неиспользуемые поле и параметр IReadRepository<Classifier> удалены. IReadRepository<Subdivision> остаётся для внутреннего чтения перед обновлением. Тела сохранённых операций, транзакции, блокировки, работа с sequence, ParentId/Path, статусы, versions, UTC-аудит, проверки permissions и области доступа не менялись.

Конкурентное создание теперь выполняет CreateFromDtoAsync: ID и числовой SubdivisionId назначаются сервером. Observer собирает точные ID всех тестовых узлов, включая новый, вместо фиксированного диапазона числовых кодов. Проверяются наличие всех узлов, согласованность ParentId/Path, аудит нового узла и путь родителя после ожидаемого commit конкурирующего переноса. Все шесть сценариев ожидания advisory lock сохранены, как и откат после SQL-сохранения переноса.

Реестр сборок требует отсутствия ISubdivisionService и точного соответствия публичных методов SubdivisionService узкому контракту. DI проверяет единственную scoped-регистрацию и изоляцию scopes в общей/раздельной композиции, Development/Production.

Удаление публичного CLR-интерфейса, методов и параметра конструктора нарушает совместимость внешних потребителей, если они существуют. Поиск в репозитории не доказывает их отсутствие вне репозитория.

## Проверки и ограничения

- Итоговая инкрементальная сборка: 0 ошибок, 0 предупреждений. Новое nullable-предупреждение тестового прокси устранено явной проверкой MethodInfo; 25 прежних предупреждений Web остаются в исходниках.
- Полный Test-Guard.ps1 с PostgreSQL: **4 711 unit + 20 914 integration = 25 625**, код 0. Временная изолированная БД удалена.
- Сохранены проверки поиска/карточек/форм, ограничений области, версий, отказа в цикле, конкурирующих переносов, отмены и отката после SQL-сохранения. Дополнены проверками всех узлов fixture и путей/аудита DTO-создания. С учётом обновлённого динамического инвентаря и DI счётчик вырос на 12.

Рабочая БД, подключения, схема, миграции и UI не изменены. Приложение, браузер и нагрузочный стенд не запускались. Перестроение иерархии RebuildHierarchyAndPathsAsync сохранено; дополнительных гарантий его конкурентности или обработки повреждённых циклических данных эта поставка не добавляет.

Продолжение выполнено: [удалён IIpAddressService и неиспользуемый IP query-прокси SecurityService](architecture-ip-legacy-cleanup.md). Остаётся пооперационный аудит ISecurityService с сохранением атомарных Identity-операций.
