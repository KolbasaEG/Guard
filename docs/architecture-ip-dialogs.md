# Этап 1, вторая поставка: DTO форм IP

Дата: 16 октября 2026 года. Ветка: `codex/architecture-ip-search`.
Продолжение серверного поиска из `8021aef`; результат ожидает проверки пользователя.

## Что изменено

`Add`, `Edit` и компоненты полей, просмотра и оболочки IP больше не получают
`IpAddress` или `Subdivision`. Редактируемые поля представлены `IpAddressFieldsDto`,
карточка — `IpAddressDetailsDto`, варианты подразделений — `IpSubdivisionOptionDto`.
Сущность в конструкторе фильтра списка пока остаётся описанием полей согласно
плану перехода; запрос из UI не передаётся.

`GetDetailsAsync` проецирует поля IP, название подразделения и служебные сведения
непосредственно в SQL. Внутри DTO нет навигаций EF или пользователей Identity.
`GetSubdivisionOptionsAsync` возвращает только ID и название активных доступных
подразделений; Root получает все активные варианты. Оба метода проверяют Read
и область доступа на сервере до чтения и повторно перед возвратом результата.
Чтение недоступной карточки возвращает null; изменение полномочий во время чтения
прерывает операцию. Варианты не зависят от момента получения каскадного UserContext.

Команды `CreateIpAddressDto` и `EditIpAddressDto` содержат только адрес, описание,
подразделение и, для изменения, ID. Форма создаёт независимый снимок этих значений
перед ожиданием операции. Поля статуса, автора и времени через команды не передаются.
Существующая серверная запись сохраняет проверки Manage, подразделения, активности,
формата и уникальности IP, транзакцию и advisory lock; аудит задаётся доверенным
пользователем операции. Статусы и схема БД не изменены.

Оболочки CreateEntity/EditEntity/ViewEntity сохранены. Дополнительная информация
использует прежний DialogInfo/EntityInfo, принимающий карточку DTO IP; этот путь
не вызывает ISecurityService для получения пользователей. Старые вызовы DialogInfo
с BaseEntity и старые методы IIpAddressService остаются совместимыми. При переносе
следующих областей эти переходные зависимости предстоит убрать.

Браузер обычного оператора в этой поставке не проверялся; его серверные сценарии
проверены на PostgreSQL. Полный прогон миграций и конкурентное редактирование
одной карточки остаются для последующих этапов. У IP пока нет токена версии:
сохранён прежний порядок записи. Замер на 10 млн IP не повторялся, поскольку
поиск списка и алгоритм уникальности не менялись. Полная выборка адресов при
проверке эквивалентных старых строк остаётся ограничением существующей записи
и требует отдельного решения до приёмки на таком объёме.
