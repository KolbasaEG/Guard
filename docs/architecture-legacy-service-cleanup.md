# Удаление невостребованных контрактов ролей и логов

Актуальное продолжение: удалены также контракты классификаторов, сотрудников и [подразделений](architecture-subdivision-legacy-cleanup.md); в Infrastructure осталось два legacy-интерфейса. Далее — IIpAddressService. Ниже сохранён отчёт о срезе `268c5e0`.

Ветка: `codex/architecture-ip-search`. Семь инфраструктурных legacy-контрактов проверены поиском обращений в производственном коде, тестах и регистрации DI. Два удалены; пять остаются для следующего участка. Этапы 1–2 целиком не закрыты.

## Результат аудита

| Контракт | Найденные потребители и решение |
| --- | --- |
| IApplicationRoleService | Вне реализации — только реестр границ сборок. UI и проверки поиска используют IRoleSearchService; запись выполняется через IRoleAccessService. Удалён |
| ILogService | Явная регистрация и alias ILogSearchService, проверка этого alias и реестр границ. UI использует ILogSearchService. Удалён |
| IIpAddressService | SecurityService использует QueryIpAddressesAsync; также есть интеграционные проверки и UI-прокси. Пока сохранён |
| IPersonalService | Реализация, интеграционные проверки, DI и UI-прокси. Производственный UI использует узкие контракты. Требуется сверить используемые методы и перевести тестовые зависимости |
| ISubdivisionService | Реализация, проверки дерева/конкуренции/операций и UI-прокси. Требуется сверить используемые методы и сохранить покрытие атомарных операций |
| IClassifierService | Реализация и UI-прокси в тестах. Следующий кандидат на удаление после сверки вызовов методов |
| ISecurityService | Реализация и проверки Identity, политики аккаунтов, пользователей и полномочий. Требуется пооперационная сверка; атомарные Identity-операции сохраняются |

Это аудит ссылок на типы внутри репозитория. Он не доказывает отсутствие потребителей вне репозитория; удаление публичных CLR-интерфейсов и методов нарушает совместимость таких потребителей, если они существуют. Новая сборка приложения проверена целиком.

## Изменения

- ApplicationRoleService реализует только IRoleSearchService. Удалены query-делегат, чтение полных сущностей и невостребованные обёртки записи над IRoleAccessService; ненужные зависимости logger и IRoleAccessService исключены из конструктора.
- LogService реализует только ILogSearchService. Удалён GetLogsAsync с IQueryable и его единственная зависимость от logger. Регистрация ILogSearchService прямая; LogService по-прежнему исключён из Scrutor, ApplicationRoleService регистрируется сканированием.
- Тела обоих SearchAsync побайтно по тексту после нормализации переводов строк совпадают с предыдущим коммитом. Сохраняются серверные permissions, повторная проверка исполнителя, фильтры, SQL-пагинация, DTO и отмена. Запись ролей и транзакции не изменены.
- Граница Infrastructure теперь допускает ровно пять оставшихся legacy-интерфейсов и проверяет отсутствие двух удалённых. Дополнительно проверяется, что оба сервиса предоставляют только DTO-поиск. DI проверяет единственную scoped-регистрацию и изоляцию между scopes в общей и раздельной композиции, Development и Production.

## Проверки и ограничения

Сборка решения: 0 ошибок, 25 прежних предупреждений. Полный скрипт с PostgreSQL: **4 711 unit + 20 849 integration = 25 560**, код 0. Временная изолированная БД удалена. Число проверок изменилось на 6 суммарно: добавлены guards, прежние динамические проверки удалённых типов больше не выполняются. Счётчик не равен числу тестовых сценариев.

Существующие проверки поиска ролей и логов выполнялись на PostgreSQL: фильтрация, стабильная пагинация, сортировка, отказы в доступе, смена исполнителя/отзыв Root и отмена. Проверки записи ролей остаются в полном runner. Рабочая БД, подключения, схема, миграции и UI не изменены. Приложение, браузер, нагрузочный стенд и публикация не запускались.

Следующий участок: IClassifierService — перевести тестовые прокси на IClassifierManagementService, сверить методы без потребителей и удалить старую границу, сохранив проверки доступа и записи.
