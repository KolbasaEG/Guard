# Этап 1, четвёртая поставка: DTO карточек подразделений

Ветка: `codex/architecture-ip-search`, база поставки: `b156619`.
Продолжение утверждённого перехода к слоистому монолиту с явными контрактами.

## Результат

Формы создания, редактирования, просмотра и перемещения подразделений используют
`SubdivisionDetailsDto`, `SubdivisionParentOptionDto`, `SubdivisionClassifierOptionDto`.
В этих компонентах больше нет сущностей, EF-запросов и фильтрации потомков по Path.
`ToFields()` создаёт независимый снимок разрешённых полей для существующих
`CreateSubdivisionDto` / `EditSubdivisionDto`. Версия карточки передаётся при
редактировании и перемещении; системные поля не попадают в команды редактирования.

Новые методы `ISubdivisionService`:

- `GetDetailsAsync(id)` — SQL-проекция полей, версии, названий связей и аудита.
- `GetEditorOptionsAsync()` — активные доступные родители, активные типы органа
  и прежний набор статусов подразделения. Справочные значения содержат составной
  ключ Type/Code и название; полные сущности не загружаются.
- `GetMoveParentOptionsAsync(id)` — активные доступные родители с исключением
  узла и всей его ветви. Заблокированный/неактивный узел и некорректный путь отклоняются.

Каждый метод использует собственный контекст, `AsNoTracking` и проекцию до
материализации. Запросы в одном контексте выполняются последовательно.
Карточка требует Subdivisions.Read, архив — ReadArchive, удалённые доступны
только Root. Нет доступа/записи — возвращается null без раскрытия причины.
Варианты редактора и перемещения требуют Read и Write. Сервер ограничивает
подразделения областью IDataAccessScopeService; Root получает явный полный доступ.
Перед возвратом повторно проверяются пользователь, полномочия и множество
доступных подразделений; изменившийся доступ отклоняет результат.

Общий `DialogInfo` совместимо принимает DTO подразделения. Автор и редактор
получаются проекцией Email, без загрузки пользователей через SecurityService.
Формы сохраняют CreateEntity/EditEntity/ViewEntity и существующие стили.
Сохранение блокирует повторную отправку; закрытие отменяет операцию, поздний
результат не закрывает следующий диалог и не показывает уведомлений.
Ошибка загрузки не оставляет доступную для сохранения пустую карточку.

## Проверки

- Сборка .NET 10: успешно; оставшиеся предупреждения относятся к прежнему коду.
- Итоговый запуск runner: **1334 проверки пройдены**, дополнительно **15 HTTP-проверок**
  собственного пароля/выхода. Временная БД, сервер и временные файлы стенда удалены
  штатным завершением runner.
- Runner включает проверки SQL-проекции, области и Root, архива/удалённых,
  отсутствия Read/Write, активных родителей, составных ключей справочников,
  исключения потомков, пустого пути, изменения доступа и отмены.
- Проверки форм: переключение редактирование/просмотр при отзыве доступа,
  заблокированные и архивные статусы, повторная отправка, снимок команды,
  закрытие во время сохранения, поздняя загрузка, повторный Dispose,
  ошибка загрузки вариантов перемещения.
- Проверки записи: устаревшие версии редактирования и перемещения,
  запрет переноса в потомка, согласованность ParentId/Path после перемещения.
- Браузер на изолированном стенде: просмотр в режиме API, служебные сведения
  с Email автора, создание и редактирование синтетического подразделения,
  перемещение к выбранному родителю и повторное открытие карточки, закрытие диалогов.
  Локальный режим включён только в созданной runner временной БД.

## Оставшиеся границы

Прежние entity/query-методы сервиса сохранены для совместимости других областей.
Внутри UpdateFromDtoAsync пока остаётся прежнее чтение сущности: UI его больше
не использует. Изменение самой операции записи относится к следующим этапам.
Конструктор фильтра списка по-прежнему использует сущность как описание полей.
Схема БД, миграции и алгоритм записи/перемещения дерева не изменены.

Несколько запросов карточки/вариантов не образуют RepeatableRead-снимок;
вариант выбора может устареть до сохранения. Проверки записи выполняются
сервисом заново. Гонки одновременного перемещения разных ветвей и нагрузочный
тест этой поставкой не проверялись. История миграций и браузер оператора также
не входят в выполненную проверку; доступ оператора проверен на PostgreSQL.

Следующий объём: серверный поиск и DTO форм классификаторов, затем оставшиеся
области по общему плану. Ветка ожидает проверки пользователя; merge/push и
рабочее развёртывание не выполнялись.
