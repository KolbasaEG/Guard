# Проверка целостности снимка API в Application

Дата: 17 октября 2026 года. База: `e9a17c2`, ветка `codex/architecture-ip-search`.

ApiSnapshotValidator перенесён из Infrastructure в Application без изменения содержимого, namespace и публичной сигнатуры. Он использует DTO, Domain и независимые helpers проверки и копирования полей. EF, HTTP, конфигурация и новые пакеты не потребовались.

Сохранены проверки внешних ключей и дубликатов, справочных пар, дат, полей сотрудника и подразделения, циклов дерева и принадлежности головному подразделению. Заданные в снимке родители перекрывают сохранённые при проверке объединённого дерева; исходный словарь не меняется. Явное головное подразделение может сохранять внешнего родителя. Режим allowMissingReferences допускает недостающие ссылки при загрузке дельты, но сохраняет проверку неполных пар, известных циклов и известных посторонних корней.

События выхода сравниваются по UTC с точностью микросекунды. Учитывается самое позднее событие из ответа и сохранённых маркеров. Совпадение даты записи сотрудника с этим событием запрещено как неоднозначное состояние. Нормализация полей выполняется на временных сущностях; входной снимок не изменяется. Прежние ArgumentException проверки полей и EntityRuleException проверки целостности сохранены.

DirectoryApiClient по-прежнему выполняет предварительную проверку. ApiSnapshotApplier загружает сохранённые справочники, родителей и события, повторно проверяет дельту со строгими ссылками и применяет изменения в существующей инфраструктурной операции. Транзакции, блокировки, аудит, HTTP и сохранение не переносились и не менялись. Валидатор не проверяет полномочия и не является самостоятельной операцией импорта.
