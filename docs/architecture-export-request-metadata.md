# Метаданные подключения при создании экспорта

Дата: 17 октября 2026 года. Ветка: `codex/architecture-ip-search`, база `e67bce5`.

DataExportService больше не зависит от IHttpContextAccessor: операция получает только IClientIpAccessor из Application. Web-адаптер ClientIpAccessor читает текущий RemoteIpAddress через существующий ClientIpAddress.Get; сохраняются нормализация IPv4-mapped IPv6 и null вне HTTP либо при отсутствии адреса. Адаптер не сохраняет предыдущий адрес и не читает сырые заголовки Forwarded/X-Forwarded-For. Обработка доверенных прокси в middleware не меняется.

Автор задания по-прежнему определяется IPermissionService, а не метаданными подключения или формой. DTO экспорта не расширялся. IP не является подтверждением доступа. Порядок проверки полномочий, блокировки, транзакции и аудита после commit сохранён; независимый контракт не требует ASP.NET. Модель, миграции, настройки и рабочие данные не менялись.

Web регистрирует ровно один scoped-адаптер; Infrastructure его не регистрирует. Проверены обе последовательности композиции в двух средах и разрешение реального графа зависимостей. В Application теперь 37 интерфейсов: 34 сервисных контракта и 3 порта чтения доступа.

Проверки: сборка без ошибок, 25 существующих предупреждений Web. Полный прогон через scripts/Test-Guard.ps1: **4 711 unit + 21 019 integration = 25 730**. PostgreSQL-проверки выполнены на временной изолированной БД с удалением в finally. Новые сценарии проверяют null без запроса/адреса, IPv4, mapped IPv4, IPv6, игнорирование сырых заголовков, отсутствие сохранённого адреса предыдущего запроса. Сценарии команд экспорта проверяют сохранённый IP и автора из отдельного контекста до аудита, тот же IP в событии, отмену до сохранения и существующие сбои аудита после commit.

Поиск по Application и Infrastructure/Core/6-Services не обнаружил HttpContext, IHttpContextAccessor или AuthenticationStateProvider. Технический критерий этапа 2 выполнен в пределах [матрицы приёмки](architecture-stage-acceptance.md). Account остаётся явным request-scoped HTTP/Identity-адаптером. Это не пользовательская приёмка и не разрешение слияния.

Следующий участок: индексируемая проверка уникальности IP с сохранением эквивалентности IPv4/IPv6/CIDR и стратегией существующих неканонических значений. Браузер и нагрузка на 10 млн IP / экспорт 100 тыс. строк в этом участке не запускались.
