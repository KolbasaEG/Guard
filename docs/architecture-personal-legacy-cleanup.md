# Удаление legacy-контракта сотрудников

Актуальное продолжение: [ISubdivisionService также удалён](architecture-subdivision-legacy-cleanup.md); осталось два legacy-интерфейса. Далее — IIpAddressService. Ниже сохранён отчёт о срезе `3b88377`.

Ветка: `codex/architecture-ip-search`. База: `51348ce`. IPersonalService удалён. PersonalService реализует четыре существующих контракта Application: IPersonalSearchService, IPersonalDetailsService, IPersonalEditorService и IPersonalStatusService. В Infrastructure остаются IIpAddressService, ISubdivisionService и ISecurityService. Этапы 1–2 целиком не закрыты.

## Аудит и изменения

Производственные потребители IPersonalService вне его реализации не найдены. Тестовые регистрации и прокси переведены на конкретные контракты поиска, карточки, редактора и статусов. Тесты карточки и поиска больше не используют общий прокси. Существующие проверки назначения IP и обновления версии формы сохранены.

Удалены шесть старых методов чтения:

| Метод | Потребители до изменения |
| --- | --- |
| GetAllActiveSubdivisionsAsync | Не найдены; редактор использует GetSubdivisionOptionsAsync с DTO |
| QueryPersonalsAsync | Не найдены; одноимённый метод SecurityService использует собственный IReadRepository и не зависит от PersonalService |
| GetByIdAsync | Только проверки полномочий и операций: переведены на GetDetailsAsync/GetEditorAsync |
| GetAllActiveAsync | Не найдены |
| GetBySubdivisionIdAsync | Не найдены |
| GetBySubdivisionPathAsync | Не найдены; удалён и его частный IsValidPath |

CreateAsync(Personal) и UpdateAsync(Personal) сохранены как private: их вызывают DTO-операции редактора. Тела оставшихся операций не изменены. Удалены неиспользуемое поле и параметр IReadRepository<Subdivision>, скорректированы тестовые конструкторы. Серверные permissions, область подразделений, проверки ссылок и статусов, блокировка режима Local/API, версии, аудит и владение контекстами сохранены.

Гонка создания сотрудника и переключения режима теперь запускает CreateFromDtoAsync. DTO не принимает ID новой записи: независимый observer ищет её по уникальному тестовому PersonalNumber, проверяет отсутствие частичного сохранения, а после commit сверяет возвращённый ID. Все четыре порядка завершения и ожидание advisory lock остаются в сценарии.

Scrutor продолжает регистрировать четыре узких интерфейса. Проверки общей/раздельной композиции в Development/Production подтверждают единственную scoped-регистрацию каждого и изоляцию между scopes. Реестр границ требует точного соответствия публичных методов реализации четырём интерфейсам и отсутствия IPersonalService.

Удаление публичного CLR-интерфейса, методов и параметра конструктора нарушает совместимость внешних потребителей, если они существуют. Поиск внутри репозитория не доказывает их отсутствие вне репозитория.

## Проверки и ограничения

- Сборка решения: 0 ошибок, 25 прежних предупреждений; последующая инкрементальная сборка после добавления проверок — 0 ошибок и предупреждений.
- Полный Test-Guard.ps1 с PostgreSQL: **4 711 unit + 20 902 integration = 25 613**, код 0. Временная изолированная БД удалена.
- Дополнительно проверены отказы read-only пользователю в обновлении DTO и всех пяти операциях статусов, сохранность полей/версии/статуса после отказов и соответствие возвращённого DTO-операцией ID сохранённой записи в трёх успешных вариантах гонки режима.
- Прежние проверки поиска, карточки, редактора, IP-назначений, смены области доступа, конфликтов, отката и независимых контекстов выполнены в полном runner. Инвентарь сборок и DI обновлён; итоговое число проверок выросло на 39 с учётом удаления старого типа из динамических проверок.

Рабочая БД, настройки подключения, схема, миграции и UI не изменены. Приложение, браузер и нагрузочный стенд не запускались.

Следующий участок — ISubdivisionService: пооперационный аудит чтения и записи, перевод тестовых зависимостей с сохранением проверок materialized path, переноса дерева, отката и конкуренции. IIpAddressService пока используется SecurityService и требует отдельной сверки.
