# Поиск пользователей: шестая поставка этапа 1

Дата: 16 октября 2026 года. Ветка: `codex/architecture-ip-search`.

## Результат

Список `/users` получает `UserSearchResult` (`Items + Count`) через `ISecurityService.SearchUsersAsync(UserSearchRequest, CancellationToken)`. Компонент больше не строит LINQ/EF-запрос и не рассчитывает состояние пароля. Прежний `QueryUsersAsync` сохранён для совместимости остальных потребителей.

Поиск выполняет проверку `Users.Read`, получает снимок серверной области подразделений, сужает запрос, применяет фильтр, считает количество, сортирует с дополнительным `Id`, выбирает страницу и проецирует поля в существующий `UserDto`. Материализация происходит внутри `IReadRepository.QueryAsync`, пока контекст открыт. Доступ Root ко всем пользователям сохраняется; обычный читатель видит только пользователей сотрудников своей области, пустая область возвращает пустой список.

После чтения сервис повторно проверяет пользователя, Root, permissions и набор доступных подразделений. При изменении доступа результат не выдаётся. Время для расчёта блокировки и срока пароля фиксируется один раз на запрос. Правила временной/административной блокировки, обязательной смены пароля и включения политики срока сохранены.

`UserSearchQuery` разрешает только `Id`, `UserName`, `Email`, `PersonalId`, `AccountBlockReason`, `LastActivityAtUtc`, `MustChangePassword`. Фильтры строятся типизированными выражениями без Dynamic LINQ: строки, nullable Guid и DateTimeOffset, bool. Проверяются операции, типы, UTC, глубина (16), количество условий (100), размер списка строк (1024), сортировка и размер страницы (1–100). Модель Identity не используется конструктором фильтра Web: добавлена отдельная `UserFilterFields`.

`UserListQuery` преобразует условия Radzen в независимый `ExportFilter`, включая перевод дат браузера в UTC, и повторяет серверную валидацию. После «Применить» изменение редактора не влияет на текущий поиск. Компонент сохраняет отмену предыдущей загрузки, защиту от поздних результатов и очистку данных при ошибке; `Dispose` сделан идемпотентным.

- `Guard/Core/6-Services/DTOs/UserSearchRequest.cs` — параметры и результат.
- `Guard/Core/6-Services/SecurityService.Search.cs`, `SecurityService.cs`, `ISecurityService.cs` — операция, зависимость политики аккаунтов и контракт.
- `Guard/Core/6-Services/UserSearchQuery.cs` — разрешённые поля, фильтрация и сортировка.
- `Guard/Components/Pages/Users/Index.razor`, `Index.razor.cs`, `UserListQuery.cs`, `UserFilterFields.cs` — вызов поиска и адаптер фильтра.
- `Guard.IpRules.Tests/UserSearchIntegrationTests.cs`, `UserSearchUiTests.cs`, `UserListTests.cs` — серверные и компонентные проверки; runner и временный браузерный стенд дополнены.

## Границы поставки

Формы создания/редактирования, операции Identity, роли и журналы не переносились в этой поставке. Список пользователей не имеет переключателей статусов или иерархии: новые элементы не добавлялись. Проверки масштаба 200 тысяч сотрудников относятся к общему этапу приёмки и здесь повторно не запускались. `ExportFilter` пока служит общим контрактом условий; физическое выделение проектов и устранение зависимости остальных потребителей от Identity остаются следующими этапами плана.

Ветка ожидает проверки пользователя; слияние и развёртывание не выполнялись.
