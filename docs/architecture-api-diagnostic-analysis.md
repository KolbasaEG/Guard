# Независимая диагностика снимка API в Application

Дата: 17 октября 2026 года. База: `346466e`, ветка `codex/architecture-ip-search`.

ApiDiagnosticAnalyzer перенесён из Infrastructure в Application без изменения содержимого файла, namespace и публичной сигнатуры. Алгоритм использует только DTO и BCL; новые зависимости и DI-регистрации не потребовались. Он собирает нарушения, а не применяет снимок и не заменяет строгий ApiSnapshotValidator.

Сохранены накопление ошибок полей и ссылок, признаки FoundLocally, дубликаты, циклы ответа и объединённого дерева, головное подразделение, UTC и микросекундная точность событий выхода. При повторном ID дерево диагностики использует первого родителя из ответа; при объединении с локальными данными родитель ответа перекрывает сохранённый. Результат содержит идентификаторы, названия полей и коды нарушений без значений персональных полей. Входные DTO и локальные словари не изменяются.

ApiDiagnosticService остаётся в Infrastructure: проверка Root до загрузки и перед анализом, обязательная дата и уровень логирования, advisory lock, HTTP, чтение локальных данных, протоколирование, отмена и освобождение блокировки сохранены. Анализатор не выполняет эти обязанности. Диагностика по-прежнему не применяет данные.

## Проверки

- Сборка решения: 0 ошибок, 25 прежних предупреждений.
- 11 прежних проверок метода ApiDiagnosticTests.Run перенесены без изменения тела в ApiDiagnosticAnalyzerTests в UnitTests: локальные ссылки, накопление ошибок, отсутствие персональных значений в результате, циклы, отмена и дерево из 10 000 узлов. Три проверки доступа к сервису остались в IntegrationTests; смешанные проверки головного подразделения и миграций сохранены.
- Добавлена 61 unit-проверка: сохранность входов, события выхода и их приоритет, UTC и границы микросекунды, обязательные поля, длины с пробелами, годы, конечная численность, код справочника 0, неполные пары, локальные ссылки, головное подразделение, приоритет родителей и дубликаты. Одна новая явная проверка границ подтверждает принадлежность Application; общий обход типов проверяет отсутствие дубликатов.
- Полный скрипт с временной PostgreSQL-БД: **4 237 unit + 20 846 integration = 25 083**, код 0. Чистый прирост — 62 относительно 25 021; перенос 11 проверок не увеличивает покрытие. Временная БД удалена runner.
- Независимая сборка UnitTests: 0 ошибок и предупреждений, 4 237 проверок; из производственных DLL только Domain и Application. После отказа MSBuild внутри песочницы без диагностик сборка успешно повторена вне неё.

Рабочие подключения, данные, схема, миграции и UI не менялись. Браузерный и нагрузочный режимы, публикация не выполнялись. Ветка ожидает проверки пользователя; слияние не выполнено.

Этапы 1–2 остаются открытыми. Следующий участок — выделить SynchronizationSchedule из файла инфраструктурного сервиса в Application и независимо проверить календарные границы и условия запуска. Workers, очереди, locks и атомарные операции остаются отдельной ответственностью Infrastructure.
