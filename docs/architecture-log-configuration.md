# Граница настройки логирования

Дата: 16 октября 2026 года. Продолжение этапа 1 в ветке `codex/architecture-ip-search`.

## Результат

Панель Logs получает и сохраняет неизменяемый `LogConfigurationDto` через
`ILogConfigurationService`. `ApplicationLogLevel` содержит шесть уровней:
Verbose, Debug, Information, Warning, Error, Fatal. Контракт не зависит от Serilog.
Явное преобразование уровней остаётся в серверном `LogConfigurationService`.

Из компонента удалены зависимости от `LoggingLevelSwitch`, `DynamicLoggerManager`
и `LogLevelPersistenceService`. Чтение возвращает активную конфигурацию процесса,
а не смесь значения из файла и текущего переключателя. Менеджер читает пару
«число сессий + уровень» под тем же lock, который защищает применение конфигурации.
При ошибке сохранения остаётся прежняя пара.

## Доступ и поведение

- Чтение требует `Logs.Read`. Сохранение требует `Logs.Configure`; по действующему
  каталогу это право доступно только Root. После RequireAsync повторно проверяется
  снимок исполнителя, используемый для диагностического сообщения.
- Сервер проверяет диапазон сессий 1–10000 и отвергает неизвестные значения enum.
  Проверки и отмена выполняются до построения нового логгера и записи файла.
- Файл `logsettings.json` сохраняет прежний формат Serilog. Загрузка при старте
  приложения и регистрации DI не изменены. Миграция БД не требуется.
- Менеджер сохраняет существующие порядок persistence → переключение → Dispose
  прежнего логгера и синхронизацию доставки событий. Его механизм sinks не переработан.
- Панель не сохраняет значения до успешного чтения, блокирует повторную отправку,
  передаёт независимый DTO и применяет подтверждённый результат. Закрытие отменяет
  запросы; поздние результаты и ошибки не обновляют закрытую панель.
- Если первоначальное чтение не удалось, нужно обновить страницу; сообщение об
  ошибке объясняет это действие. Сохранение без успешного чтения заблокировано.

## Проверки

- `dotnet build Guard.slnx --no-restore -v quiet`: 0 ошибок, 34 существующих предупреждения.
- Полный runner с `--postgres Guard/appsettings.json`: 1623 проверки, код выхода 0,
  отдельная временная PostgreSQL-БД удалена после завершения.
- Браузерный runner: также 1623 проверки и 15 отдельных HTTP-проверок собственного
  пароля/выхода. После проверки сервер остановлен, временная БД удалена.
- После небольшого уточнения защиты закрытого компонента и добавления двух проверок
  отмены чтения повторены сборка и локальный runner: 856 проверок, код выхода 0.
  PostgreSQL повторно после этих изменений не запускалась: серверные операции БД
  последними изменениями не затронуты.
- Новые проверки охватывают все шесть отображаемых уровней, серверные ограничения,
  отказ доступа и потерю полномочий, отмену, загрузку формы, повторную отправку,
  неизменность команды, подтверждённый результат и закрытие при чтении/сохранении.
  Существующие проверки менеджера подтверждают доставку событий при параллельной
  смене конфигурации, освобождение sinks и сохранение прежнего логгера при ошибке
  persistence; дополнительно проверяется сохранность полного снимка настроек.
- В браузере на синтетическом стенде проверены автоматическая первая загрузка,
  активные Information/100, все шесть вариантов, выбор Warning без сохранения,
  переход на вторую страницу таблицы и повторное чтение Information/100 после
  перезагрузки. Реальное сохранение файла из браузера и восстановление после
  перезапуска процесса в этой поставке не проверялись. Сортировка, фильтры,
  real-time и диалог строки не изменены и повторно вручную не проверялись.
