# Независимые фильтры IP, подразделений и классификаторов

Дата: 16 октября 2026 года. Ветка: `codex/architecture-ip-search`. База: `ef02f36`.

## Результат

В `Guard/Core/6-Services/SearchFilterValidation.cs` добавлены `IpSearchFilter`, `SubdivisionSearchFilter`, `ClassifierSearchFilter`: неизменяемые наборы разрешённых полей, явные типы BCL и проверка сериализованного `ExportFilter`. Вложенные пути описаны строковыми ключами; проверка не обращается к сущностям, EF, Identity, Radzen и expression API.

Три Web-адаптера `IpListQuery`, `SubdivisionListQuery`, `ClassifierListQuery` используют независимые правила. Соответствующие серверные `SearchQuery.ValidateFilter` делегируют им проверку; публичные сигнатуры сохранены. SQL-построители по-прежнему самостоятельно проверяют условия. Наборы полей сортировки берутся из тех же неизменяемых описаний. В `Guard/Components` больше нет обращений к классам `SearchQuery`.

Сохранены вложенные строковые поля, поведение null и пустых условий, регистронезависимые сравнения и регистрозависимые `In/NotIn`, проверка числовых типов и UTC. Ограничения: глубина 16, 100 узлов с учётом корня, 1024 строки в списке. Преобразование календарных дат остаётся в Web. Изменения не затрагивают запросы области доступа, статусы, иерархию, пагинацию, загрузку данных и разметку.
