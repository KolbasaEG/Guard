# Skills и среда Codex для Guard

Настройка от 19 октября 2026 года. Четыре проектных Skill восстановлены по текущим требованиям и инструкциям Guard: исходные копии со старого компьютера отсутствовали, идентичность им не заявляется. Производственный код, тестовые runner и подключения не менялись.

## Проектные инструкции

| Skill | Путь от корня | Назначение |
| --- | --- | --- |
| guard-verify-change | `.agents/skills/guard-verify-change/SKILL.md` | Выбор и выполнение проверок изменения |

Они самодостаточны в контексте репозитория, не требуют дополнительных скриптов или обязательной привязки к ролям. Общие правила остаются в AGENTS.md. Все четыре файла прошли системный quick_validate.py; автоматический выбор не отключён.

В `.codex/config.toml` установлен `project_doc_max_bytes = 65536`: текущая цепочка инструкций превышает стандартные 32 КиБ. Предел дочерних потоков остаётся 2; sandbox, модели, рассуждения и разрешения не переопределены. Значение в файле не доказывает эффективную настройку ранее открытого чата.

## Установленные внешние дополнения

Источник — официальный [dotnet/skills](https://github.com/dotnet/skills), ревизия `10d85e25fb42d5f65c568d5e979a005ee69eecb3`, лицензия MIT. Marketplace `dotnet-agent-skills` зарегистрирован штатной командой Codex с фиксацией этой ревизии. Установлены и включены плагины:

| Плагин | Версия | Skills |
| --- | --- | --- |
| dotnet-blazor | 0.1.2 | author-component, collect-user-input, configure-auth, coordinate-components, create-blazor-project, fetch-and-send-data, plan-ui-change, support-prerendering, use-igniteui-blazor, use-js-interop |
| dotnet-data | 0.1.5 | create-datadriven-aspnetcore, optimizing-ef-core-queries |

Установка: `$HOME/.codex/plugins/cache/dotnet-agent-skills/<плагин>/<версия>`. В пользовательском config.toml у обоих `enabled = true`. Манифесты предоставляют только Skills, без MCP и hooks. Копировать их в пользовательскую папку Skills не нужно. Все проверенные относительные Markdown-ссылки внутри навыков пакетов разрешаются.

Отдельно через системный skill-installer из той же ревизии установлены в `$HOME/.codex/skills/`:

- `test-anti-patterns`;
- `assertion-quality`;
- `test-gap-analysis`;
- `test-analysis-extensions` — справочные материалы для анализа, не самостоятельная задача и не разрешение на запуск дополнительных агентов.

Это отдельные Skills, не установка пакета dotnet-test целиком. `run-tests` и миграционные/генерирующие Skills не устанавливались. ZIP-режим установщика столкнулся с длинным Windows-путём в посторонней тестовой фикстуре; успешная установка выполнена через его поддерживаемый `--method git`.

Guard использует собственные исполняемые Check-runner. Внешние примеры framework не заменяют этот стек; поиск тестов учитывает Program.cs и существующие Run/RunAsync. Для проверки утверждений анализируется семантика Check, а не наличие атрибутов Test/Fact. Внешние примеры Blazor/Data не разрешают менять Radzen на Ignite UI, создавать проект, обновлять .NET или применять миграции вне поручения.

Исходные upstream-навыки сохраняются без переписывания. Справочный `test-analysis-extensions` содержит upstream-поля `user-invocable`/`disable-model-invocation`; это не доказательство отдельного технического запрета Codex. Не вызывайте его как workflow: читайте известный файл `extensions/dotnet.md` при необходимости. Строгий валидатор skill-creator допускает более узкий набор frontmatter, чем некоторые upstream-файлы; их YAML, ресурсы и фактическое обнаружение проверяются отдельно.

## Валидатор Skills

Чтобы не изменять встроенный Python Codex, создано отдельное окружение:

`$HOME/.codex/venvs/skill-validation`

В нём Python 3.12 и PyYAML 6.0.3 с официального PyPI. Для Windows PowerShell:

```powershell
& "$HOME/.codex/venvs/skill-validation/Scripts/python.exe" -X utf8 -B `
  "$HOME/.codex/skills/.system/skill-creator/scripts/quick_validate.py" `
  .agents/skills/guard-verify-change
```

UTF-8 нужен для русских инструкций; `-B` отключает создание pycache. Аналогично проверяются остальные три проектных Skill. Системный skill-creator также прошёл этот валидатор. Не копируйте venv на другой компьютер как переносимую установку: выберите совместимый Python и восстановите зависимость там отдельно.
