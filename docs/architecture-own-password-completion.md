# Завершение собственной смены пароля

Дата: 16 октября 2026 года. Ветка: `codex/architecture-ip-search`.
Первый участок остатка этапа 2 из [аудита записи](architecture-write-operation-audit.md).

## Поведение

После успешного IdentityResult пароль и security stamp уже сохранены. OwnPasswordService теперь отдельно обрабатывает ошибку RefreshSignInAsync: возвращает новый OwnPasswordChangeStatus.SignInRequired. Предыдущие значения enum сохранены, новый статус добавлен в конец. Исключения до подтверждения записи не преобразуются в этот статус.

HTTP endpoint ChangeOwnPassword возвращает для этого результата 200 с JSON `requiresSignIn: true` и понятным сообщением. Обычный успех сохраняет прежний пустой ответ 200; Unauthorized и Rejected сохраняют 401/400. Авторизация и antiforgery остаются обязательными.

Статическая страница и интерактивный диалог показывают «Пароль изменён. Не удалось обновить сеанс. Войдите заново с новым паролем», скрывают форму, очищают введённые пароли и предлагают ссылку на вход. Диалог блокирует повторную отправку после подтверждённого изменения. При обычном успехе страница перенаправляет на главную, диалог перезагружает circuit как раньше. Во время отправки диалог использует IsSaving вместо IsLoading, сохраняя форму для FormData при ожидании загрузки JS-модуля.

PolicyUserManager.ChangePasswordAsync отделяет доставку PasswordChanged от подтверждённой записи: исключение IAuditService регистрируется через технический ILogger, успешный IdentityResult сохраняется и cookie может обновиться. Событие отправляется один раз, очередь или гарантированная повторная доставка не вводятся. Остальные операции PolicyUserManager, включая AddPasswordAsync, этой поставкой не меняются.

При неизвестном серверном результате/ошибке транспорта интерактивная форма предлагает проверить вход с новым паролем до повторной смены. Автоматического повтора команды нет. Если хранилище сохранило пароль, но потеряло подтверждение записи, адаптер не заявляет ни подтверждённый успех, ни подтверждённый откат. Ошибка самого ChangePasswordAsync продолжает передаваться вызывающему коду.

## Проверки

- Сборка Guard.slnx с отдельным OutputPath и UseAppHost=false: 0 ошибок, 25 существующих предупреждений.
- `dotnet Guard/obj/search-contract-build/Guard.IpRules.Tests.dll`: **18 755 проверок** (на 56 больше предыдущего среза).
- `node --test Guard.IpRules.Tests/change-password.test.mjs`: **7 тестов** — родительский и 6 сценариев протокола.
- `git diff --check`: без ошибок.

Новые проверки используют настоящий PolicyUserManager с тестовым Identity store и отдельной сохранённой копией пользователя. Покрыты неверный текущий пароль, несовпадение подтверждения, политика нового пароля, отказ IdentityResult, ошибка хранилища до записи, потеря подтверждения после записи, отказ cookie, отказ аудита и оба отказа вместе, отмена обновления cookie после записи. Проверяются hash старого/нового пароля, stamp, UTC/поля политики, число записей, отсутствие повторов и вызовов последующих шагов при неподтверждённом результате.

Проверки обработчиков обеих форм подтверждают состояние сообщения, очистку секретов и запрет повторной отправки диалога. JS-тесты исполняют действующий модуль с подменёнными fetch/location, проверяют reload, локальный login с префиксом приложения, requiresSignIn, validation, 500 и транспортный обрыв без повтора. Это не полноценный браузер и не проверка реальной доставки cookie.

PostgreSQL, полный HTTP-стенд и визуальная проверка браузером в этой поставке не запускались: изменения проверены на тестовом store и обработчиках, без запуска приложения с рабочими подключениями. Доставка уже начавшегося HTTP-ответа или сетевой обрыв после сохранения не могут быть гарантированы новым статусом. Существующий периодический отзыв открытых соединений не добавляется, настройки IP-доступа и 2FA не меняются.
