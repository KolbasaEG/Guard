# Валидация и копирование редактируемых полей в Application

Дата: 17 октября 2026 года. База: `10500a8`, ветка `codex/architecture-ip-search`.

`EntityInputValidation` и `EntityWriteMapping` перенесены из Infrastructure в Application без изменения содержимого файлов и namespace. Они используют только Domain, DTO и прикладное исключение конфликта версии. Публичный API не расширен: оба класса остаются internal. Application предоставляет внутренний доступ Infrastructure и двум тестовым сборкам через InternalsVisibleTo; Web в список не входит. Это доступ ко всем внутренним типам сборки, а не ограничение на два конкретных класса; список получателей проверяется автоматически.

Сохранены порядок и побочные эффекты валидации: обрезка пробелов обязательных строк и отчества, прежняя обработка остальных строк, границы длины, годы 1900–2100, конечная неотрицательная численность и полнота справочных пар. Наличие справочника, полномочия, область подразделений, транзакции, проверка актуальной версии и сохранение остаются ответственностью существующих операций Infrastructure. При ошибке валидация может уже нормализовать предыдущие поля, как и до переноса.

Копирование по-прежнему переносит только поля DTO. Идентификаторы записи, версия, аудит, жизненный цикл, внешние служебные поля, навигации и коллекции не меняются. SubdivisionId сотрудника входит в редактируемые поля; право его изменения проверяет операция. Внутренний helper сам по себе не является границей доступа.

## Проверки

- Сборка решения: 0 ошибок, 25 прежних предупреждений.
- Все 174 прежние проверки EntityWriteMappingTests перенесены из IntegrationTests в UnitTests без изменения файла. Проверяются чтение/запись всех полей DTO, очистка значений, сохранение служебных полей и ссылок навигаций, JSON и отсутствие сущностей в API DTO.
- Добавлено 166 проверок валидации: null/пустые строки/пробелы, точная и превышенная длина, нормализация до проверки длины, годы, дробная/отрицательная/NaN/бесконечная численность, все справочные пары и конфликт версии, включая Guid.Empty.
- Три новые проверки границ сборок подтверждают единственное владение внутренними типами и список friend assemblies. Существующие проверки допускают только Domain/BCL в зависимостях Application и сохраняют 35 сервисных контрактов.
- Полный скрипт с временной PostgreSQL-БД: **4 046 unit + 20 855 integration = 24 901**, код 0. Временная БД удалена runner. Прирост относительно 24 732 — 169 проверок; перенос 174 проверок между runner не увеличивает покрытие.
- Независимая сборка и запуск UnitTests: 0 ошибок и предупреждений, 4 046 проверок. В каталоге из производственных сборок только Domain и Application. После отказа MSBuild внутри песочницы без диагностик проверка повторена вне неё.

Рабочие БД, подключения, миграции и UI не менялись. Браузерные и нагрузочные проверки, публикация не выполнялись. Изменения остаются в ветке задачи до проверки пользователя; слияние не выполнялось.

Этапы 1–2 остаются открытыми. Следующий участок — ApiSnapshotValidator: он использует независимый ApiSnapshot и перенесённые helpers; проверить возможность переноса правил целостности и существующих тестов без изменения импорта, транзакций и сверки с сохранёнными данными. Остаток по EF/Identity, транспортным адаптерам, workers и неопределённому исходу commit сохраняется в общей сверке.
