# Проверки Guard

В решении четыре производственных и два тестовых проекта. Оба тестовых проекта — обычные executable runner на .NET 10 без нового test framework. `dotnet test` не выполняет эти проверки.

| Проект | Назначение | Зависимости |
| --- | --- | --- |
| Guard.UnitTests | Разбор IPv4/IPv6/CIDR, IP-допуск и IP-полномочия, permissions, область подразделений, переходы статусов, политика аккаунтов, валидация и копирование редактируемых полей, целостность и диагностика снимка API, расписание синхронизации, отмена и ошибки портов | Domain и Application; без пакетов, ASP.NET, EF, Web, БД и файлов конфигурации |
| Guard.IntegrationTests | EF-модель и миграции, DI, Identity, HTTP, рендеринг/UI, статические ресурсы, PostgreSQL, браузер и нагрузочные замеры | Четыре производственных проекта; без зависимости от UnitTests |

Часть быстрых проверок остаётся в IntegrationTests: они используют инфраструктурные правила, Identity или Web. Перенос в UnitTests допускается после устранения этих зависимостей в производственном коде. Тесты границ сборок остаются здесь, поскольку проверяют все четыре сборки.

## Запуск из корня репозитория

Для [центра уведомлений](notifications.md) выполнен полный прогон: **4 713 unit + 22 907 integration** на временной PostgreSQL-БД, включая новую миграцию, изоляцию адресатов, отзыв Root/экспортного права, конкурентное прочтение, повторную доставку, восстановление инцидента, очистку и результаты реальных workers экспорта/синхронизации. Браузерный стенд дополнен синтетической историей из 27 уведомлений; проверены первая загрузка, страницы, фильтр непрочитанных, синхронизация прочтения между вкладками, светлая/тёмная темы и реальный экспорт с toast, счётчиком и переходом из уведомления к готовому документу. Стенд остановлен, временные БД удалены. Исторические результаты ниже относятся к прежним участкам.

Последний участок: [индекс пагинации сотрудников](architecture-personal-pagination-index.md).
Полный функциональный прогон — **4 711 unit + 21 073 integration = 25 784**;
проверены миграция вниз/вверх на существующих данных, стабильный порядок одинаковых ФИО,
статусы и серверная область доступа. Отдельный сравнительный Benchmark завершён:
200 тыс. сотрудников, 500 тыс. IP; медиана глубокой DTO-страницы 1110,4 → 38,7 мс,
SearchAsync с Count после индекса — 77,5 мс. Временные БД удалены, рабочая БД не изменялась.

После [браузерной проверки](architecture-browser-acceptance.md) и UI-исправлений
тот же полный прогон повторён в Browser-режиме. Дочерний host дополнительно прошёл
20 HTTP-проверок собственного пароля/выхода и 70 локального Account; они не входят
в 25 784. Ограничение: сохранение скачанного файла встроенным браузером не подтверждено.

```powershell
dotnet restore Guard.slnx
dotnet build Guard.slnx
./scripts/Test-Guard.ps1
./scripts/Test-Guard.ps1 -Mode Postgres
```

Скрипт запускает сначала UnitTests, затем IntegrationTests, проверяет наличие обеих сборок и останавливается при ненулевом коде. Он не выполняет сборку автоматически. Для Release добавьте `-Configuration Release`; для общего изолированного каталога сборки — `-BinaryDirectory Guard/obj/search-contract-build`.

Раздельный запуск:

```powershell
dotnet run --project Guard.UnitTests/Guard.UnitTests.csproj --no-build
dotnet run --project Guard.IntegrationTests/Guard.IntegrationTests.csproj --no-build
dotnet run --project Guard.IntegrationTests/Guard.IntegrationTests.csproj --no-build -- --postgres Guard/appsettings.json
```

IntegrationTests сохраняет режимы `--postgres`, `--browser`, `--benchmark` с одним аргументом пути конфигурации. Скрипт принимает соответствующие `-Mode Postgres`, `-Mode Browser`, `-Mode Benchmark` и `-SettingsPath`. UnitTests не принимает эти параметры и не читает конфигурацию.

`--postgres` создаёт и удаляет временную изолированную БД через локальное подключение; рабочие данные и настройки не меняются. Базовый режим IntegrationTests поднимает отдельные HTTP-host для тестов, но не запускает Program приложения или seeding. Браузерный режим запускает отдельный стенд на временной БД; перед запуском убедитесь, что порт 5079 свободен. Нагрузочные проверки запускаются отдельно и не входят в обычный прогон.

Прежний `Guard.IpRules.Tests` переименован в `Guard.IntegrationTests`. Команды и числа в исторических архитектурных отчётах относятся к состоянию до разделения. Полный прежний набор теперь выполняется двумя runner; сравнивать следует сумму их проверок. Новая проверка графа проектов дополнительно запрещает зависимости production → tests, tests → tests и расширение зависимостей UnitTests.
