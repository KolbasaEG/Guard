# Серверный маппинг DTO записи

Дата: 16 октября 2026 года. Ветка: `codex/architecture-ip-search`. База: `ffeb317`.

## Результат

Из `DTOs/EntityWriteDTOs.cs` удалены зависимость от Entities и методы `From(entity)`/`ApplyTo(entity)` трёх DTO: `PersonalFieldsDto`, `SubdivisionFieldsDto`, `ClassifierFieldsDto`. Они содержат только поля BCL; имена, типы, значения по умолчанию и контракты команд Create/Edit сохранены.

Те же присваивания перенесены во внутренний `EntityWriteMapping` в серверном namespace `Guard.Core.Services`. `From` имеет три перегрузки, `ApplyTo` — три внутренних метода расширения. Все найденные потребители `From` переведены на серверный класс; существующие вызовы `ApplyTo` разрешаются как внутренние расширения, а не методы DTO. Web не использует этот класс. После выделения проектов маппинг относится к серверной реализации операций, DTO — к Application.

Состав полей записи не расширен. ID, Version, аудит, жизненный цикл, ParentId/Path, служебные признаки и времена синхронизации по-прежнему изменяются операциями отдельно. Разрешённый SubdivisionId сотрудника остаётся полем команды; проверка доступа сохраняется в сервисе. Серверная валидация, транзакции и SQL-проекции редакторов не менялись. `ToFields` моделей редактора остаётся в DTO: он преобразует один независимый контракт в другой, без сущностей.
