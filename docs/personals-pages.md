# Страницы сотрудников

Страницы `/personal` приведены к стандарту списка IP-адресов и общим оболочкам библиотеки.
Список по-прежнему использует `PersonalListItemDto` и серверный `SearchAsync`: доступ к списку
не требует права чтения полной карточки. Проекция, ограничения области и материализация
остаются в сервисе; перенос на `QueryPersonalsAsync` потребовал бы `Personals.ReadDetails`.

## Поведение

- Компактная таблица, пагинация сверху справа, русские подписи и итог поиска.
  Переключатель статусов центрирован; панель действий справа. Существующий экспорт CSV сохранён.
- `Subdivision.Name` используется для сортировки подразделения; прежнее `SubdivisionName`
  остаётся допустимым для совместимости. Неподдерживаемые поля и направления отклоняются.
  Сортировка заканчивается уникальным ID.
- Фильтр применяется одной кнопкой. Дерево условий копируется и проверяется до замены
  применённого снимка. Редактирование конструктора не влияет на обновление и пагинацию.
  Очистка условий вступает в силу после «Применить».
- Первое отображение загружает данные после получения контекста доступа. Изменение контекста
  сбрасывает страницу; отзыв доступа к архиву или удалённым возвращает активный режим.
  Предыдущая загрузка отменяется, поздние результаты игнорируются.
- Формы используют CreateEntity/EditEntity и PersonalFields. Ошибка начальной загрузки
  запрещает сохранение. Вводимые данные не очищаются при ошибке сохранения.
  Редактирование допускается только для Inserted/Modified; сервис повторяет проверку.
- Обязательны фамилия и имя; отчество необязательно. Предельные длины: компоненты ФИО
  100, фамилия и инициалы 250, личный номер 50. Год службы необязателен,
  при заполнении — 1900–2100; правило проверяется в форме и сервисе.
- Карточка группирует сведения о сотруднике, службе, подразделении, учётной записи и IP.
  Идентификаторы, коды и аудит открываются через EntityInfo. Статусы переведены на русский,
  даты отображаются в часовом поясе браузера. Ошибка загрузки оставляет понятное сообщение.
- Назначения IP сохраняются отдельно. Вложенное сохранение обновляет версию формы,
  сохраняя введённые поля, только если бизнес-поля серверной записи совпадают с исходными.
  Чужие изменения не принимаются автоматически: сохраняется защита от конфликта.
- Уведомления об успехе и обновление списка зависят от успешного результата диалога.
  Закрытие/отмена не считаются сохранением. Закрытие компонентов отменяет их запросы.

Модель БД и миграции этой задачей не изменены. В EntityInfo исправлена привязка кнопки закрытия.

## Автоматические проверки без БД

```powershell
dotnet build Guard.slnx --no-restore -m:1 -v quiet -p:OutputPath=bin/PersonalsReview/
dotnet run --project Guard.IntegrationTests/Guard.IntegrationTests.csproj --no-restore -p:OutputPath=bin/PersonalsReview/
```

Отдельный OutputPath нужен, когда запущенный Guard блокирует обычный каталог сборки.
Приложение командами выше не запускается; запускается только тестовая программа.

PersonalPagesTests проверяет снимки и допустимость фильтров, стабильную сортировку,
трансляцию сортировки и DTO-пагинации в SQL PostgreSQL без подключения,
серверное отклонение недопустимого года, отмену/поздние результаты загрузки,
очистку списка при ошибке, запрет сохранения неподготовленной формы и неактивных записей,
безопасное обновление версии после IP, а также реальную HTML-разметку карточки и её
скрытие при отсутствии ReadDetails. Это не заменяет интерактивную проверку браузера.

## Проверка в изолированной среде

1. Открыть список без нажатия обновления; проверить русский пейджер, размеры колонок,
   положение статусов и кнопок, отображение при узком окне.
2. Применить вложенные И/Или, изменить условия без применения, обновить/отсортировать/
   сменить страницу: действует прежний снимок. Очистить условия и применить.
3. Проверить сортировки всех колонок и соседние страницы с одинаковыми значениями.
4. Проверить «Только свои» и «Свои и подчинённые», включая Root без подразделения:
   при отсутствии подразделения список пуст.
5. Проверить архив с/без ReadArchive, удалённые только для Root, допустимые переходы
   статусов, запрет редактирования и назначения IP для неактивных записей.
6. Добавить/изменить сотрудника с пустым отчеством и без года, проверить длины,
   границы года и ошибки; проверить недоступность сохранения при сбое справочников.
7. Проверить карточку, дополнительную информацию, часовой пояс браузера и закрытие
   обоих диалогов. Проверить пользователя с Read без ReadDetails.
8. Из формы редактирования сохранить IP: введённые поля сохраняются, последующее
   сохранение сотрудника успешно. Повторить с параллельной правкой другой сессии:
   чужие изменения не перезаписываются.
9. Закрыть диалоги без сохранения: нет уведомления об успехе. Проверить возврат после
   успешных операций и экспорт с/без Export.
10. Отозвать права/сменить доступную область при открытой странице, вызвать ошибку
    загрузки, быстро менять страницы и закрывать диалоги во время запроса.

Интерактивные сценарии и интеграция PostgreSQL требуют отдельной тестовой БД.
Рабочее приложение для проверки этой задачи не запускалось.
