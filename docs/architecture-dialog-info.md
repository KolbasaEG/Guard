# Служебные сведения и оставшиеся границы UI

Дата: 16 октября 2026 года. Ветка: `codex/architecture-ip-search`. Продолжение поставки `39048d1`.

`Shared/DialogInfo` получает сведения только из `IpAddressDetailsDto` или `SubdivisionDetailsDto`. Удалены параметр `BaseEntity`, резервная загрузка авторов через `ISecurityService.GetUserByIdAsync`, неиспользуемые внедрения классификаторов и UI-сервисов. Все три найденных вызова (IP Edit, Subdivision Edit/Move) уже передавали DTO; их параметры и разметка не менялись. Автор, редактор, идентификатор и даты берутся из `EntityInfoDto`. Сохраняются EntityInfo, BrowserTimeService, соответствующее право чтения и закрытие диалога без данных.

## Актуальная статическая проверка

Поиск выполнен в Guard и Guard.IpRules.Tests по C#/Razor, включая Shared. Это проверка найденных зависимостей, а не полное доказательство независимости всей будущей сборки Application.

| Область | Результат и дальнейшее действие |
| --- | --- |
| Широкие ISecurityService, IIpAddressService, ISubdivisionService, IClassifierService | В Components/Shared больше не внедряются. Серверные реализации и тесты продолжают использовать совместимые API; удалять их без отдельной ревизии нельзя |
| EntityListQuery в Library | Snapshot используется адаптерами фильтров UI. Capture/Sort и их построитель выражений вызываются только RefactorTests; это оставшийся IQueryable API Web. Следующая поставка — перенести проверки на действующий путь Snapshot → независимый фильтр → серверный запрос и удалить неиспользуемую реализацию |
| Account | Прямое использование UserManager/IdentityOptions остаётся в техническом IdentityRevalidatingAuthenticationStateProvider. Его роль в проверке security stamp сохраняется; это адаптер Web, а не прикладной контракт |
| Core/6-Services | Семь legacy-интерфейсов IPersonalService, IIpAddressService, ISubdivisionService, IClassifierService, ISecurityService, IApplicationRoleService, ILogService всё ещё содержат query API. Каталог нельзя целиком переносить в Application: требуется разнести независимые контракты и инфраструктурные реализации/совместимые API |
| Domain | Personal.User по-прежнему ссылается на ApplicationUser. Устранение связи относится к выделению Domain с сохранением EF-связи/FK/уникальности |

Проверка времени жизни контекстов, доверенного исполнителя и атомарности всех составных записей остаётся этапом 2. Уже существующие операции UnitOfWorkFactory сохраняются; наличие фабрики не закрывает аудит остальных операций. Физическое разделение проектов не начато.

## Проверки и ограничения

- Сборка Guard.slnx, отдельный OutputPath, UseAppHost=false: **0 ошибок, 25 предупреждений**. Удаление неиспользуемых полей DialogInfo устранило девять nullable-предупреждений относительно предыдущей сборки.
- Актуальный runner без параметров: **1002 проверки**. Новый DialogInfoRenderingTests рендерит настоящий компонент для IP и подразделения, в компактном и полном режиме, с разрешённым и запрещённым чтением. Проверяются автор, редактор и идентификатор. Тестовая DI не регистрирует Identity/репозитории/сервисы сущностей.
- Это статический HTML-рендеринг: браузерная инициализация часового пояса, интерактивное закрытие и визуальный осмотр диалогов в этой поставке не проверялись. Серверные операции, доступ и схема не изменялись; PostgreSQL и HTTP-хост повторно не запускались.
- Рабочие данные, подключения и миграции не менялись. Ветка ожидает проверки пользователя; merge/push не выполнялись.

Следующий шаг — удалить неиспользуемый query API EntityListQuery после замены тестов на действующие адаптеры, затем завершить реестр контрактов перед этапом 2. Этап 1 целиком пока не закрыт.
