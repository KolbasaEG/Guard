# Эталон компонентов: IP-адреса

Раздел `/ip` использует Radzen и общие оболочки Library. Его организация служит
образцом для новых областей; правила IP-доступа и проверки сервиса остаются
предметной логикой IpAddresses и не копируются в другие сущности.

Порядок переноса подхода, ограничения образца и критерии приёмки собраны в
[инструкции фронтенд-субагенту](frontend-subagent.md).

## Список

- `Page.razor` задаёт маршрут и разрешение; `Index` управляет отображением списка.
- Верхняя панель содержит постоянно доступный фильтр на всю ширину, без пустой
  аналитики. Начальная высота — 180 px, изменяется разделителем.
- Статусы расположены по центру панели, кнопки обновления, области и добавления —
  справа. На узком экране статусы переходят в отдельную центрированную строку.
- Клик по записи открывает просмотр. Отдельная кнопка открывает редактирование
  активной незаблокированной записи при наличии права управления. Кнопки действий
  не вызывают одновременно обработчик строки.
- Таблица использует DTO; конструктор фильтра — сущность. Маппинг, подсчёт,
  сортировка и пагинация выполняются до материализации результата.
- Фильтр применяется только кнопкой «Применить». Очистка условий и нажатие
  «Применить» снимают фильтр. Редактирование конструктора не меняет действующий
  снимок при обновлении, сортировке или переходе между страницами.
- Новые условия, статус или область возвращают список на первую страницу.
- Пустой список означает отсутствие подходящих записей. Ошибка очищает данные,
  записывается в лог и показывается уведомлением без дополнительной плашки.
- Новая загрузка отменяет предыдущую; поздний результат не заменяет актуальный.

`Index.LoadData` вызывает `IIpAddressService.SearchAsync(IpSearchRequest)` и
применяет `Items + Count`. Путь своего подразделения и актуальные полномочия
получает сервер; запрос из UI их не задаёт. Сервер выполняет область доступа,
статус, выбранную иерархию, фильтр, Count, сортировку с Id, пагинацию и DTO-проекцию.
`IpListQuery` только копирует Radzen-условия в сериализуемый ExportFilter;
`IpSearchQuery` проверяет и исполняет их без Radzen и Dynamic LINQ. Тот же
исполнитель используется для IP-экспорта, формат существующих заданий сохранён.

## Область отображения и экспорт

Сервис всегда проверяет право чтения и серверную область доступа. Переключатели
списка только сужают полученный доступ.

Root по умолчанию видит режим «Все доступные»: все разрешённые записи выбранного
статуса, включая общие адреса без подразделения. Этот режим доступен только Root
и не требует привязки к сотруднику. При его отключении действуют «Только свои»
и «Свои и подчинённые»; они ограничивают также Root. Отсутствующий или некорректный
путь собственного подразделения даёт пустой результат в обоих режимах.

В существующий экспорт передаются тот же режим статуса, область, применённый
фильтр и сортировка. Режим «Все доступные» передаётся как `AllSubdivisions`;
сервер экспорта повторно проверяет Root и разрешение экспорта.

## Диалоги

- Ширина простых форм IpAddresses — 640 px, максимум — ширина окна минус 24 px.
- Добавление: `CreateEntity`; редактирование: `EditEntity`; просмотр: `ViewEntity`.
- `IpAddressFields` общий для добавления и редактирования: `Variant.Text`,
  `RadzenStack` с `Gap="5px"`. Проверки IPv4/IPv6/CIDR сохраняются на форме
  и в сервисе. Общие адреса без подразделения создаёт и изменяет только Root.
- `IpAddressDetails` использует `RadzenTable`: ячейки с `padding:2px`, значок
  и подпись слева, значение справа. Пустое значение — «—», длинное переносится.
- `IpAddressDialogBody` выбирает оболочку. Явный `ReadOnly`, отсутствие права
  управления и неактивный статус исключают редактирование и кнопку сохранения.
- Служебные сведения открываются через `EntityInfo` в компактном `DialogInfo`.
  Авторы и даты не дублируются в основной карточке.

## Жизненный цикл и обратная связь

`isLoading` — загрузка записи, `isSaving` — сохранение, `isLoaded` — успешное
получение записи. Сохранение блокирует ввод, повторную отправку и открытие
служебных сведений, сохраняя содержимое формы. После ошибки введённые значения
остаются доступны для исправления и повторной отправки.

Закрытие отменяет запрос. Результаты загрузки и сохранения после закрытия или
уничтожения компонента не меняют UI, не показывают уведомления и не закрывают
следующий диалог. Успех возвращается только после успешного ответа сервиса.
Список обновляется только после `EntityDialogResult.IsSuccess`.

Ошибки поля показываются валидаторами рядом с полем. Ошибки операций и информация
о доступе показываются через `NotificationService`; внутренние исключения идут
в лог. Одинаковое состояние доступа не вызывает повторных уведомлений при
перерисовке. Позиционирование уведомлений соответствует общему стандарту проекта.

## Проверка перед переносом подхода

Проверяются первое открытие списка, применение и очистка фильтра, сортировка,
пагинация, статусы, область Root и оба режима иерархии, совпадение списка с
экспортом, просмотр по строке и редактирование отдельной кнопкой, валидация,
повторная отправка, отмена, закрытие и восстановление после ошибки.

`IpAddressReferenceTests` покрывает область отображения, снимок фильтра и гонки
диалогов. `IpIndexTests` проверяет фильтры и список на PostgreSQL.
`IpSearchFilterTests` сверяет совместимость фильтров, `IpSearchUiTests` проверяет
отмену и поздние ответы, `IpSearchIntegrationTests` — серверный контракт,
подразделения, статусы, сортировку, валидацию и смену доступа на PostgreSQL.
Интеграционные проверки запускаются только на временной изолированной БД;
рабочее приложение не запускается автоматически ради проверки сборки.

Браузерный режим `--browser` создаёт в той же временной БД дополнительные
IP-записи для проверки нескольких страниц и архивного/удалённого режимов.
Для отдельного каталога сборки путь к `Guard.dll` передаётся через
`GUARD_TEST_APP_DLL`; настройки подключения рабочего приложения не меняются.
После завершения стенда временная БД удаляется штатным тестовым кодом.
